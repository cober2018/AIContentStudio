# AI Content Studio 文章/图文 V1 对齐方案（三轮讨论稿，待用户确认）

> 面向后续执行者：本文件是规划，不是实施授权。先完成对应 OpenSpec propose 并获得用户确认，再以 executing-plans 逐项实施；本轮不写业务代码、不新增测试代码、不对外发布。

**Goal:** 在现有平台上，把三个产品的真实素材转成用户认可的文章/图文，并完成全渠道可用分发、可信状态记录与最小反馈回收。

**Architecture:** 复用事实、选题、稿件版本、审核资产、连接器与工作流；首批补类型化冻结证据、母稿依赖、稿件期素材、完整审批与独立人工交付目标，再扩全渠道和自动分发。保留模块化单体，不新建另一套内容中心。

**Tech Stack:** 现有 FastAPI、SQLAlchemy、React/Vite、Celery/Redis、SQLite/PostgreSQL、文件/对象存储与 wewrite。

**状态：** 本地源码核对、ChatGPT 三轮讨论和独立文档复核完成；本版已吸收讨论结论及最终审阅提醒。用户已确认按 M1 继续落地：公众号 + X 线程成品包与人工回填，公众号自动草稿不作为硬门槛。OpenSpec 提案已创建并通过严格校验；尚未执行 apply，也没有进行真实模型、平台账号、远端草稿或公开发布验收。

## 1. 需求基线与边界

来源：[自媒体平台对比总结](https://chatgpt.com/g/g-p-6ab247272c188191ac5443303450d0fa-aicontentstudio/c/6ab23aa1-ce20-83e9-9acb-c6ffeda87191)。以用户最后关于三产品矩阵、文章 V1 / 视频 V2 的说明为主，架构回答作为候选设计，不作为已确认实现清单。

已补读该对话附件 `AI_Content_Center_Requirements_R2.md` 的全文，含 A01–A64 与 AT01–AT20。附件本身区分用户确认、推导必需、默认规划和外部依赖；不能把全部建议误当用户逐项批准，也不能在“做基本需求”时静默删掉其中的业务闭环。

- 量化平台：提供复盘、统计、因子研究、图表，以及研究和工程过程。
- 媒体采集分析工具：提供原始出处、时间戳、转写片段及第三方观点。
- 内容中心：接收上游成果和用户输入，生产、修改、适配、审核、分发和回收反馈。不得重做量化计算或媒体抓取。
- V1：文章、短帖、线程、图文和成品图卡。保留已有抖音脚本能力，但不拿它代替文章渠道，也不把视频成片纳入本期。
- V2：视频脚本、分镜、配音、授权数字人、真实演示、合成质检、视频分发；复用 V1 的证据、版本、素材与分发记录。

### 渠道范围

| 形态 | V1 规划渠道 | 最小完成定义 |
| --- | --- | --- |
| 长文章 | 公众号、头条、百家号、知乎文章、B站专栏/图文、搜狐号、企鹅号、网易号 | 原生适配稿、最终排版、实际素材、来源/声明、交付包与状态 |
| 问答 | 知乎回答 | 关联明确问题，问题导向的回答结构；不能把文章直接改标签 |
| 图文 | 小红书 | 可预览并导出的真实图片组、顺序、正文与标签，不止图片提示词 |
| 社交文本 | X、微博 | 单帖/线程等形态独立建模；X 单帖、线程、长帖与 Articles 分别列入 V1 成品适配，不能以线程样本替代其余形态；账号资格影响分发能力，不将未核验权限假定为可用 |

上述 11 个渠道来自原对话的需求整理，不等于账号、接口、平台服务现状已逐一核验。平台能力必须按“账号 × 内容形态 × 分发动作 × 核验时间”记录；条件不满足显示待验证/不可用，不伪装已接入。

### 暂定假设及其影响

1. 先为用户自己的产品矩阵服务：不在 V1 同步做商业多租户、套餐计费、独立桌面助手和全新工作流引擎。对外开放前必须另补真实鉴权与隔离。
2. 暂按“全渠道成品覆盖，自动化按已验证能力提供”拆计划，但不把全部人工交付默认成最终 V1 达标。若主要渠道必须自动送达草稿箱，账号权限联调需前置为准入条件，不能靠导出来替代验收。首批 M1 的人工交付建议也须用户确认。
3. 无明确预算和上线期限，不承诺日期、平台收益、生成耗时或自动化比例。

### 必须保住的三条一致性

1. **证据一致：** 已选事实的值、日期、单位、出处及第三方观点归属，在某一母稿版本内不可漂移。上游修订创建新证据版本，并标出受影响的母稿和平台稿，不覆盖历史。
2. **编辑一致：** 正文、结构内容、图卡文案、引用和校验结果必须指向同一版本。手工修改后不能继续导出旧 structured_json 或沿用旧校验。
3. **交付一致：** 先形成完整、不可变且可预览的内容候选，再批准该内容哈希；目标授权另绑定账号、动作和已批准版本。截断标题或换图需重审；仅换账号通常重做目标授权，若规则/声明/正文也变化则同时重审内容。界面可一次确认，记录不可混同。

## 3. 最短可行路线

| 路线 | 取舍 | 判断 |
| --- | --- | --- |
| 直接增加渠道模板 | 快，但仍是各写各的，不能保证素材和交付一致 | 不作为主路线 |
| 增量补齐内容主链，再扩渠道与分发 | 保留现有资产，每一步可验收，减少后续返工 | 建议采用 |
| 一次实现未来 SaaS / 视频 / 新调度架构 | 大量新基础设施，推迟用户第一篇可用成品 | 不纳入 V1 |

目标流程：

```text
上游结果 / 建设记录 / 用户原稿
    → 候选选题与来源 + 产品归属（尚非正式 Topic）
    → 冻结证据 → 创建正式 Topic → 确认母稿版本
    → 平台适配 → 真实封面/图卡 → 统一校验
    → 不可变成品候选 → 预览并批准内容哈希 → 目标账号/动作授权
    → 各渠道独立交付（自动草稿 / 人工接续）
    → 远端回执或待核对 → 效果与问题反馈
```

当前创建 Topic 要求 frozen FactPack；规划保留这条门槛。没有齐备证据的想法/原稿先保留为来源与候选，不得凭空制造 Fact 来通过建题。候选采纳与正式 Topic 创建是两个动作，需在提案中明确最小持久化方式。

## 4. 先交付 M1，再补全 V1（实施前分别提案）

### M1：已有文章的受控跨渠道复用

建议首批采用公众号 + X 线程：一篇有来源、用户满意的现有稿，不强制重写，经两种形态适配与审批后，生成成品包、实际人工交付并回填结果。X 为建议样本渠道，尚未获得用户选定；不以 X API、远端草稿或收益资格为已具备前提。

```text
已有原稿与来源 → 类型化证据审核/冻结 → Topic + 母稿版本
    ├─ 公众号稿 + 实际封面 → 完整内容审批 → 账号授权 → 人工交付目标
    └─ X 有序线程 + 所需素材 → 完整内容审批 → 账号授权 → 人工交付目标
各目标独立等待/回填 → 链接或凭证（人工确认）→ 满意度与后续反馈
```

M1 必需范围：

- [ ] **类型化证据：** 在 FactPackItem 或同等小型扩展上冻结值与原文，不新建通用证据平台。事实/事件沿用 Fact；第三方引述引用 Source 片段、说话者和定位；作者观点保存真实原稿片段及作者确认。非 Fact 条目允许空 fact_id，但不允许空包直接批准，也不把整篇“作者观点”标签用于豁免客观断言。引述数字不能进入全稿通用允许数字池。
- [ ] **不可变母稿：** 保留 Topic 根对象，新增小型 MotherRevision，平台任务固定引用其版本。原件先于编辑保存；证据不足可保留为候选，不得假造事实建题。普通母稿升级只提示，不替换旧绑定；证据更正/权利失效/审批撤销暂停相关未交付目标并要求复核。
- [ ] **最小编辑一致性：** 母稿和平台 Draft 保留 Markdown 真源，X 逐帖边界明确；structured_json、引用、图卡、检查与导出载荷带 input_hash。改标题、正文或线程顺序后相关派生物失效，重建并校验前不能宣称成品就绪。无需更换编辑器或先做完整段落锁定产品。
- [ ] **稿件期素材和审批：** AssetMedia 可关联 Draft，在批准前准备实际封面/必要图片。文件使用独立版本或内容哈希路径，受批准清单引用的素材不被覆盖或删除。先形成不可变内容清单再审批其哈希；ContentAsset 继续保存批准资产，不创建同义资产中心。
- [ ] **语义审查完成状态：** 检查的严重程度与覆盖状态分开。事实冲突、虚构亲历、错归属、无证据客观断言不能直接放行；警告需有处置理由。模型未运行、失败、截断未覆盖、报告过期均不是通过，可补跑或由人工完成缺失范围并留记录。误报只能有依据地复核结案，不以“已读”消除阻断。
- [ ] **目标与反馈：** 增加小型 DeliveryTarget，绑定产品、平台、形态、账号、动作、批准内容及授权版本；人工等待互不阻塞，重复操作不重复创建意图。人工回执记录操作者、时间、实际动作、链接/凭证与核验方式，不把人工声明包装成系统自动核验；最少一条满意度/读者反馈可关联 Topic 或新候选。事件追加复用 AuditLog。
- [ ] **公开包与内部证据分离：** 包含最终文案、实际素材、顺序、可公开来源、声明、清单及操作说明，不默认打包内部 FactPack、私有原文或不具备公开权利的素材。资料公开权限与外部模型使用权限分别检查。
- [ ] **旧入口收口：** Studio 的实际外部调用边界统一验门槛，旧工作流定义、旧运行恢复、失败重试和直接调用均不能绕过。M1 不启用远端建稿；缺新快照、授权、已验证能力或自动交付可靠性时不调用 wewrite。不是仅隐藏按钮或修改新模板默认值。历史存档可标注后下载，但不得自动变成新规则已批准。
- [ ] **有界生成与兼容：** M1 的模型生成/检查仍需超时、调用与成本上限，失败和降级可见。若走现有异步队列，必须保证业务提交先于可靠投递，不能保留 commit 前消费竞态。旧三渠道数据可读、可追溯；不通过迁移伪造历史证据。此处不要求完整自动发布调度器。

M1 验收必须覆盖：一篇已满意原稿不被重写；非数值作者观点和第三方引述正确归属；修改活 Fact 不改变旧冻结证据；正文变化使派生物失效；反复上传不改变历史素材；换账号不能沿用旧目标授权；检查不完整时不能宣称通过；两个成品包可预览、实际人工交付有凭证且至少一条反馈；一个目标等待不拖住另一个；旧交付/重试入口不能绕过门槛。

重复提交复用同一交付意图，回执更新需可防重；中断或结果不明进入人工核对，不自动新建发送。不能将本地记录防重承诺成“人工操作或远端平台绝对只发布一次”。旧版本只要仍获有效批准且目标明确绑定就可使用；证据失效、审批撤销或绑定不匹配的版本不得继续交付。

**仅生成包 = 包就绪；实际人工交付并回填 = 人工交付闭环；真实账号远端草稿 = 另一项自动分支验收。M1 不是全渠道 V1，也不替用户确定最终自动化下限。**

首个建议 OpenSpec 提案名为 `add-evidence-bound-article-handoff`，覆盖上述 M1、最小迁移与历史标记。暂不纳入远端建稿启用、新自动发布接口、复杂排期、全部投递恢复设施、其他渠道、视频、数字人、SaaS 和计费。后续开启自动交付必须单独通过可靠性和真实账号验收，不是直接打开开关。

这意味着实施 M1 时可能需要让旧的 Studio 自动建稿路径暂时转人工；必须在提案中明示并由用户确认，本轮没有停用任何现有功能。

### 后续 A：补齐上游接入与完整编辑能力

M1 是下述工作面的最小纵向切片，不要求先做完整 A 再开始使用。A/B 可在 M1 稳定后按接口边界并行推进，C 自动交付另有准入，D 完成全 V1 验收；不重复建设 M1 已有对象。

目标：覆盖量化、建设记录、媒体观点与现有稿的完整接入及编辑体验；补高级候选管理、完整锁定/比较等能力。下面清单是 V1 完整能力，不再全部作为第一篇成品的前置。

相关已有文件：`apps/api/app/models.py`、`routers/facts.py`、`routers/fact_packs.py`、`routers/external.py`、`routers/topics.py`、`routers/generate.py`、`routers/reviews.py`、`services/generation/orchestrator.py`、`services/asset_media.py`、`services/workflow_engine.py`、`services/workflow_templates.py`、`tasks/worker_tasks.py`；前端 `pages/Topics.tsx` 及其现有稿件/资产页面。

- [ ] 规范：定义母稿与证据快照、现有稿件导入、审查/交付状态、外部副作用边界和历史兼容；不得把“已导出”改名为“已发布”。
- [ ] 输入：补上游版本化来源契约（来源产品/记录/版本、时间、单位、定位、素材权利、公开与模型使用范围），保留原件；复用现有文件入口与一种自动接入，不要求上游改内部数据库。重复包不重复建题，坏包进入待处理；缺资料可生成补充请求单。
- [ ] 候选采纳：上游候选进入 Source/Fact 的核验链，保留转写片段定位、说话者、观点归属与样本范围；采纳候选不等于确认其中观点。证据整理并冻结后才创建正式 Topic，再关联母稿；不能以 ExternalContent 入库成功代替这一步。
- [ ] 证据：补不可变事实值快照或等价保护，保留事实类型、时间和出处；待核验第三方观点不得作为自有事实或亲历结论。
- [ ] 内容：以 TopicBrief 作为聚合入口，建立最小母稿版本和确认机制；新建/导入原稿后能局部修改，保留修改历史。平台稿绑定明确母稿 revision，不默认使用“最新稿”。
- [ ] 编辑：保留原稿“不重写、只适配”路径，支持大纲确认、锁定事实/引文/段落、版本比较与复制回退；重生成不覆盖锁定片段。退稿原因与范文偏好保留，但不自动变成全局规则。
- [ ] 账号/产品：最小产品定位、公开材料、风格、账号和业务线配置随该样本进入主链，不推迟到数据看板才补归属。API 凭据只给交付执行器，不交给生成器。
- [ ] 审核：全部素材在批准前就绪；正文和结构同时更新或显式失效；事实、安全、素材、平台规格使用统一批准门。校验服务降级要可见，不默认为通过。
- [ ] 交付：完整载荷与账号冻结，调用前持久化交付意图；公众号适配器复用 wewrite。结果不明标待核对，禁止直接重试建稿；安全重试与重新投稿分开。
- [ ] 单目标可靠性（启用真实建稿的前提）：重复点击返回同一交付意图，并发仅能领取一次；执行前重新检查审批/账号/素材有效性。调用超时或远端可能成功但本地进程退出时，恢复为待核对而不是自动重发。设置超时、有限重试及调用上限；使用队列时提交后可靠投递并处理投递缺失。未完成这些前只开放导出，不开放新增自动建稿路径。
- [ ] 人工验收：用一份真实样本完成用户预览；读回远端草稿内容/标识或核验导出包，与冻结版本一致。没有真实账号验证时只验收导出分支，不宣称草稿箱分支完成。
- [ ] 建稿启用验收：检查重复点击/并发请求、提交前中断、远端成功后本地中断、超时未知、审批后换图和账号失效；不得重复建稿、发出未批准版本或静默丢任务。

## 5. 对象映射与兼容原则

- TopicBrief 继续作为内容项目入口；增加产品/系列/意图关联，避免并行建一个同义 ContentItem。
- FactPackItem 在冻结边界容纳事实/事件、归属清楚的第三方引述和作者观点；冻结实际值/片段及来源，不把非数值观点伪装成数值 Fact，也不放开无证据客观断言。
- 母稿是中立内容版本，不伪装成第四个媒体平台；推荐小型独立母稿版本对象，平台 ContentJob / Draft 引用它。最小字段在 M1 提案中锁定，阶段 A 再补完整编辑能力。
- Draft 保留为平台编辑版本，素材允许在稿件期挂载；ContentAsset 保留为批准的内容资产。不可变候选在审批前固定素材字节/哈希、最终排版、引用、规则和声明；审批绑定内容哈希，目标授权另绑定账号与交付动作，不能批准后再补封面。
- M1 只加小型 MotherRevision、DeliveryTarget 及现有对象扩展，事件复用 AuditLog；具体新增模块路径、迁移及回退方式在 OpenSpec 提案中确定，不提前建设通用插件或完整投递框架。
- ExportRecord 继续代表导出行为，不承担远端状态；交付目标与尝试记录负责对外副作用。
- 外部已有成稿通过显式“采纳为母稿”进入同一链路，不被迫重新生成；ExternalContent 历史记录保留。
- 已有三渠道记录不批量改写，迁移可回退；旧稿缺新证据的标记为历史未补验，不能凭迁移自动升级为通过。
- 旧证据类型默认标记为 `legacy_untyped`，不能一律填成 `fact`。提案需列出克隆、校验值、预览、生成/改写、事实检查与导出等读取路径如何兼容可空 fact_id 和冻结值；旧包可读、历史规则可追溯，但新规则下的审批与交付必须先补齐类型化证据，不允许以历史模式绕过。
