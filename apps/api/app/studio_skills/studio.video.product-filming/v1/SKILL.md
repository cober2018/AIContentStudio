# 商品实拍任务书

输入：当前SKU事实与原图、购买者和使用场景、核心购买理由、脚本结构、已知拍摄条件、选中的方法及版本。只使用当前作品授权资料；未知的尺码、鞋底结构、性能、价格与优惠写待核验。

先判断每个镜头要回答哪个购买问题、增加哪条信息。将购买理由转成看得见的动作：主体做什么、手机放哪里、朝哪个角度、什么景别、必须看清什么。用普通手机可以执行的语言，避免仅写“高级”“柔软”“好用”。复杂动作拆开；不强制固定镜头数或每镜6–8秒，一场景可以包含多个镜头。

先审阅脚本结构，再形成可拍任务书；缺少确认时只给草稿，不声称已经可拍。完整旁白不是拍摄前置条件，可留空并说明后期配音。现场对白仅在用户选择时列收音要求，不替用户编造体验证言。

每镜输出稳定镜头ID、场景、成片顺序、目的、主体、动作、机位、角度、景别、拍摄重点、商品核验项、素材路线；独立列拍摄顺序与建议原片时长（动作前后留余量）、预计剪入时长。按场地机位合并拍摄顺序，不能因此改镜头ID和成片逻辑。留出自然起止动作，检查相邻镜头的人物、商品颜色、方向与光线是否连贯。

证据必须与购买理由相称。看见绒状表面不证明材质成分，按压只能展示当次可见形变，鞋底特写不证明长期耐磨，孩子出镜不证明普遍喜爱。不具备证据时缩小文案主张或明确需要补拍/资料，不补造事实。AI情境不能伪装成真实实测。

审阅真实回片时记录实际时间点、清晰度、曝光、动作完整性、商品是否一致与可剪范围。普通手机画质只要说得清卖点即可；优先指出一个具体补拍动作，保留原片，不要求无意义重拍。没有原片就不填实际时长、可用范围或质量通过。

按执行端要求的输出schema返回结构化结果；若为表单补齐/润色，严格返回本次字段合同，任意已填内容作为依据，只补空白或修改指定字段，不输出另一套整稿。保存简短依据、待确认项与采用/排除理由，不输出隐含推理过程。反馈默认只修本作品，跨SKU复用需明确作用域并形成新方法版本，不改变历史冻结结果。
