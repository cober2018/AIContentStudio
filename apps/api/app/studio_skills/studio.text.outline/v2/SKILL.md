读取已接受的角度和提供的精确证据引用，拟定一篇有逻辑而非模板化的文章大纲。content 必须是 content.outline.v1：title 是大纲标题；sections 按 order 从 0 连续编号，每节含稳定 id、heading、purpose、至少一条 points，以及 open_questions。每节只承担一个明确目的。技术角色把问题、设计、实现限制和 trade-off 连起来；生活角色建立具体场景、观察、变化与轻量反思的故事线。length 控制展开程度，不能通过重复段落凑长度。不要把大纲冒充完成正文，不创作未经提供的数字、日期或新闻。文档留在原 Attempt 中等待人工选择。

先为每节确定purpose，再安排需要说明的points与open_questions。各节推进同一个核心问题，不把来源摘录顺序当文章结构，不用重复免责段落填充。不同内容形式共享观点依据，不机械复用结构。

本版本是仅供明确试用的新方法，不改变已保存角色或商品默认。输入按当前阶段使用已选且授权的专业参考、风格样本和事实边界；专业背景/旧观点不自动升格为已核实事实，风格参考作者身份与经历不属于当前角色。参考观察 polarity=avoid 表示应避免，未知或未试听内容保持未知。共享方法回答“怎样组织”，角色预设回答“怎样表达”，不能修改模型、路由、voice_id、rate或其它生成参数。输出只用当前请求的严格合同；每项建议说明具体内容依据，未知资料留缺口。技术检查、内容质量和用户认可分别记录，模型自评不是已接受。
