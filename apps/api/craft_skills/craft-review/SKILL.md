# craft-review：效果复盘——从平台后台读作品数据录进平台

用户在自己已登录的浏览器（ego lite，按 ego-browser skill 操作）里，模型打开各平台后台，读作品数据，录进 AIContentStudio 的效果复盘。默认由 Codex Desktop 执行，Claude Code 备用。**只读**：不点发布、删除、修改、置顶、设置权限这类按钮。

## 流程
1. `list_accounts` 看要复盘的账号（`importable` 为 true 的平台才收数据）。用户点名的平台和账号为准；没点名就把能收的都做一遍。
2. 每个账号：读这个平台那一份说明 `get_craft_skill(skill="craft-review", entry="<platform_channel>.md")`。没有说明的平台告诉用户「还没写说明」，经同意再按页面摸索，实际步骤写进最后的汇报。
3. 在 ego lite 打开平台后台，按说明读数据。优先读页面自己用的数据接口（数字是平台原值），读不到再读页面文字；不要靠截图看数。
4. 核对登录的账号：后台显示的账号名、头像和 `list_accounts` 里的对得上再录；同平台有多个账号或对不上时问用户，并记下用户说的对应。
5. `list_published_works(account_id)` 取平台里已有的发布记录。逐条对上：
   - 平台作品编号已记在记录上（`platform_item_id`）的，平台会自动认出；
   - `origin` 为 studio 的是我们做的作品：`url` 和平台作品链接相同就是同一条；没有链接时按标题对，平台上的标题常是「标题 + 正文」或去掉了标点，按开头、发布时间、时长对上。对上的把记录 id 填进 `published_content_id`；
   - 我们的作品标题常和平台上的标题完全不同（平台用的是发布文案的标题，例如作品「量化数据质量：前中后台三道防线」在平台上叫「数据错了还显示成功？量化数据的三道防线」）：同一作品在各平台的发布记录标题相同，看它在其他平台已对上的那条（链接、发布日期）来认；
   - 对不上的不填，平台会建外部作品。拿不准就不填，宁可多一条外部作品，也不要挂错。
6. `import_account_metrics`：`source.kind` 用 `platform_page`，`source.name` 写平台和页面（如「抖音创作者中心 · 内容管理」），`source.checksum` 用读到的原始数据（接口返回的原文）算 sha256；一个账号的数据来自多个接口（列表 + 单条详情）时，把各份原文按读取顺序拼起来算一个。每行带 `platform_item_id`、`url`（作品链接）、`published_at`（中国时间）。比率写 0–1 小数，数字用平台原值，平台没给的项不填。一次最多 200 行。
7. 汇报：每个账号新增 / 更新几条、批次链接，对不上或拿不准的作品列出来。数据录错时用户可以在效果复盘里整批撤销。

## 红线
- 只读；遇到登录、扫码、验证码、短信、风控：停下，请用户处理后再继续。
- 不翻太多页：默认读最近 50 条作品；用户要更多再往后读。正常节奏，不并发猛刷接口。
- 不把 cookie、token、账号信息写进汇报或文件。
- 接口原文先原样存成文件（算 checksum 也用它），再解析；长数字编号用原文里的值，不要经过 JavaScript 数字。
