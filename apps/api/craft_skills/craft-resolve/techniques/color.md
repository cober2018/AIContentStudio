# 调色

先读 `choose.md`。讲解类片子的调色目标是「正常、统一、主体清楚」，风格化只在导演稿要求时做。调色放在 Color 页节点上，不直接改素材，关掉节点就能回到原样。

### 先看示波器，不凭感觉
- 思路：屏幕会骗人，示波器不会。曝光看波形，白平衡看分量，偏色方向看矢量。
- 用在：每个需要调色的镜头，调之前和调之后各看一次。
- 不用在：AE 生成的图形镜头。
- 做法：
  - 波形（Waveform）：高光长时间贴顶 = 过曝，整体贴底 = 欠曝；主体亮度落在中段。
  - 分量（Parade）：找画面里的白或灰，RGB 三条在该处应基本齐平；哪条高就偏哪色。
  - 矢量（Vectorscope）：点云往哪个方向伸出就偏哪个色；肤色应靠近肤色线。
  - 校正：用 Offset 色轮往偏色的反方向拉，直到中性色三通道齐平、点云回到中心。
- 脚本：部分。Resolve 示波器不能脚本读取；可先导出单帧，用 ffmpeg 的 `signalstats`（亮度最小 / 最大 / 平均，以及 U/V 平均）做数值检查。
- 检查：中性色不偏；高光没有大片贴顶；暗部没有整片贴底。
- 常见错误：在不同屏幕上凭眼睛判断；混合偏色时只看分量图。
- 状态：试用
- 来源：第 9 集

### Log 素材先还原
- 思路：Log 灰片保留了更多细节，但必须先转回正常色彩空间，才能判断颜色。
- 用在：素材是 Log（Apple Log、S-Log3、V-Log、F-Log 等），画面发灰、对比低。
- 不用在：普通 Rec.709 素材。
- 做法：第一个节点用 Color Space Transform：输入选素材对应的色彩空间和 Gamma，输出 Rec.709 / Gamma 2.4（或项目设定）；也可用厂家提供的还原 LUT（`Graph.SetLUT(1, 路径)`）。曲线必须和拍摄机型对应。
- 脚本：部分。LUT 能脚本设置；Color Space Transform 需在 Color 页添加。
- 检查：对比恢复正常，肤色和中性色不灰不偏；只是「回到正常」，还没有风格。
- 常见错误：把灰片当成坏素材；随便套一个别家的 LUT。
- 状态：试用
- 来源：第 9 集

### iPhone HLG 还原（必做）
- 思路：iPhone 默认拍 HLG，达芬奇默认色彩管理会把它整体提亮（平均亮度约 190，手机上同一帧约 147），看起来就是过曝。用平台拟合的专用 LUT 把它还原成手机上看到的样子，这是还原，不算调色。
- 用在：每段实拍素材都先查：`ffprobe -v error -select_streams v:0 -show_entries stream=color_transfer -of csv=p=0 <文件>`，结果是 `arib-std-b67` 的就是 HLG。
- 不用在：SDR 素材（普通实拍、网络素材）、AI 生成画面、AE 叠层与包装（它们不是 HLG，套了会变暗变灰）；普通 SDR 实拍改走「普通实拍渲染补偿」。
- 做法：
  - 项目色彩科学用 `davinciYRGB`（不做色彩管理），时间线 Rec.709 Gamma 2.4。
  - 只给 HLG 片段套 `MCP/iphone-hlg-apple-sdr-render.cube`：`TimelineItem.SetLUT(1, "MCP/iphone-hlg-apple-sdr-render.cube")`。交付用 `-render` 版：YRGB 下带 LUT 的渲染亮度约等于 0.993×静帧 − 0.078，`-render` 已补上这一差；`iphone-hlg-apple-sdr.cube` 只在对着静帧比时用。
  - 达芬奇 LUT 列表里没有 `MCP/` 这两份时，先从仓库 `craft_skills/craft-resolve/luts/` 拷到达芬奇 LUT 文件夹下的 `MCP/`（macOS：`/Library/Application Support/Blackmagic Design/DaVinci Resolve/LUT/MCP/`），再在 Color 页刷新 LUT 列表（或重启达芬奇）。
- 脚本：能。项目设置和 `SetLUT` 都能脚本做；HLG 判断用 ffprobe。
- 检查：拿**渲染出来的文件**抽帧，和手机自己的显示帧（`AVAssetImageGenerator` 从原片取同一时刻）比平均亮度，相差几个点以内；不拿达芬奇静帧或 Viewer 比。高光没有大片贴顶。
- 常见错误：开着色彩管理再套 LUT（提亮两次）；给 SDR 素材、AI 画面、AE 叠层也套了；在 HLG 片段上再叠 `sdr-render-comp.cube`（`-render` 版已含补偿，叠了就亮 20 级）；达芬奇里看着正常就交，没比渲染文件；按第一个镜头手调亮度套到全片。
- 状态：在用
- 来源：2026-11-02 P46 实测（套 LUT 后 146.8，手机 147）

### 普通实拍渲染补偿（必做）
- 思路：`davinciYRGB`、不做色彩管理时，渲染出来的文件比达芬奇静帧暗：渲染 ≈ 0.993×静帧 − 0.078，约暗 20/255，从暗部到高光都是这个固定差。HLG 的 `-render` LUT 已经补了；没套 LUT 的普通 SDR 实拍就整片吃这 20 级。
- 用在：`davinciYRGB` 项目里每段 SDR 实拍（ffprobe 的 `color_transfer` 是 `bt709` / 未标注，不是 `arib-std-b67` / `smpte2084`），例如抖音自拍。
- 不用在：HLG 片段（已套 `-render` LUT）。AI 画面、AE 叠层是否同样变暗没验证过：渲染一次后抽帧和原图比，暗了同样补，没暗就不动。
- 做法（二选一，回执写明用的哪种）：
  - 套补偿 LUT：`TimelineItem.SetLUT(1, "MCP/sdr-render-comp.cube")`，整体 +0.078（+20/255）。
  - 从根上解决：查出是哪项项目 / 渲染设置（数据电平、渲染范围等）造成的，改设置让全片渲染和原片一致；改了设置就全片统一，**不再**套补偿 LUT（HLG 片段的 LUT 也要重新对一遍）。
  - 达芬奇 LUT 列表里没有 `MCP/sdr-render-comp.cube` 时，先从仓库 `craft_skills/craft-resolve/luts/` 拷到达芬奇 LUT 文件夹的 `MCP/` 下，刷新 LUT 列表。
- 脚本：能。`SetLUT`、ffprobe 判断、ffmpeg 抽帧都能脚本做。
- 检查：拿**渲染出来的文件**和原片在同一时刻各抽一帧比平均亮度（`signalstats` 的 YAVG，或缩小转灰度求平均），相差几个点以内。平台交付时也会逐镜头比，差超过提示线就在审阅页提示「成片比原片暗 X 级」。
- 常见错误：叠在 HLG 的 `-render` LUT 上（补两次）；改了设置又套补偿 LUT；只看达芬奇 Viewer / 静帧就交；AI 画面、AE 叠层没比就默认不补。
- 状态：在用
- 来源：2026-11-03 项目 48 / 作品 93 任务 41（未补偿的抖音自拍镜头渲染后暗约 20 级）

### 亮部暗部分开救
- 思路：整体亮度一拉，亮的过曝、暗的死黑；要只救其中一端。
- 用在：画面整体偏暗或偏亮，但问题只在一端。
- 不用在：整体曝光都偏时（先用 Offset 或 Gain 整体调）。
- 做法：Primaries 里用 Highlights / Shadows 分别调；需要更细时用 Lift（暗部）和 Gain（亮部）。
- 脚本：部分。CDL（`SetCDL`）可做整体的 Slope / Offset / Power / Saturation；分区控制需手动。
- 检查：亮部有细节，暗部有层次，中间过渡自然。
- 常见错误：只拉整体亮度。
- 状态：试用
- 来源：第 9 集

### 四个色轮分区上色
- 思路：Lift、Gamma、Gain、Offset 分别管暗部、中间调、亮部、整体，各自上色互不干扰。
- 用在：要做「亮部暖、暗部冷」之类的层次，或修只在某个亮度区出现的偏色。
- 不用在：中性色还没校正之前。
- 做法：先校正中性色 → Gain 往暖色轻推、Lift 往冷色轻推，Gamma 不动 → 每个色轮旁的亮度轮控制该区明暗。幅度小，看矢量图不过界。
- 脚本：部分（CDL 只覆盖整体）。
- 检查：只动某一区时，其他区基本不变；层次明显但不夸张。
- 常见错误：一上来就风格化；推得太重，肤色变色。
- 状态：试用
- 来源：第 9 集

### S 曲线加对比
- 思路：暗处压一点、亮处提一点，中间保持不动，层次就出来了。
- 用在：还原后仍发灰、缺层次。
- 不用在：本身对比已经很强的画面。
- 做法：Custom Curves 的 Y（亮度）曲线：左下加点微压，右上加点微提，中段斜率不变；需要修色彩平衡时再动单独的 R/G/B 曲线。
- 脚本：不能（曲线需手动）。
- 检查：曲线是平缓的 S；中间调亮度没被整体推高或压低。
- 常见错误：S 太陡，高光和暗部细节都没了。
- 状态：试用
- 来源：第 14 集

### 只改一种颜色
- 思路：某一种颜色太跳（绿太艳、背景色抢眼）时，只动它，不动别的。
- 用在：单一颜色抢主体、和品牌色冲突。
- 不用在：整体偏色（用色轮）。
- 做法：Hue vs Hue / Hue vs Sat 曲线，在目标色上加点调整色相或饱和度；范围更精确时用 HSL 限定器选出该颜色再调。
- 脚本：不能（需手动）。
- 检查：只有目标颜色变化；没有色块、断层。
- 常见错误：范围选得太宽，连肤色一起改了。
- 状态：试用
- 来源：第 9 集

### 统一全片色调（必做：粗剪后、导出小样前）
- 思路：不同机位、不同时间拍的素材，要看起来像同一部片子。只做校正和匹配，不做风格化。
- 用在：每条片子出小样前过一遍：HLG 还原之后，把曝光、白平衡拉正，同一场景的镜头对齐到一个参考镜头。
- 不用在：只有一个镜头；素材本来就正常且彼此一致时不动（成片默认不调色）；导演稿没要求的风格化调色。
- 做法：先调好一个参考镜头 → 抓静帧（`Timeline.GrabStill`）→ 其余镜头用 Shot Match 对齐到参考，或复制调色（`TimelineItem.CopyGrades`）；同一场景的镜头编进一个色彩组（`AssignToColorGroup`），共同的部分放在组的 Post-Clip 节点上。
- 脚本：部分。复制调色、色彩组能脚本；Shot Match 需手动。
- 检查：同一场景相邻镜头切换时没有色差跳变；回执写明哪些镜头做了校正、改了什么（如「shot-3 曝光压一点、偏暖拉回」）。
- 常见错误：每个镜头单独调，越调越不一样；借统一之名加风格。
- 状态：试用
- 来源：第 14 集
