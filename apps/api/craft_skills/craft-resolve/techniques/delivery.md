# 交付规格

先读 `choose.md`。装配和导出步骤、响度以 `finishing.md` 为准；这里是参数怎么选。参数用 `Project.SetRenderSettings` 一次设一个键（见 `finishing.md`）。

### 分辨率不超过素材
- 思路：1080 素材导成 4K 不会变清楚，只会变大。
- 用在：每次定时间线和交付分辨率时。
- 不用在：无。
- 做法：交付分辨率取「平台要求」和「主要素材原生分辨率」中较小的那个；竖屏讲解默认 1080×1920。个别素材分辨率不足时，只对那一段做放大（见下一节），不要整片升格。
- 脚本：能。读素材的 Resolution 属性，与时间线设置比较。
- 检查：主要素材原生分辨率 ≥ 交付分辨率。
- 常见错误：为了数字好看导出 4K。
- 状态：试用
- 来源：第 5 集

### 帧率前后一致
- 思路：时间线帧率、交付帧率、主要素材帧率不一致，就会卡顿或重复帧。
- 用在：建时间线之前（`finishing.md` 要求先定再建）和交付时。
- 不用在：无。
- 做法：时间线帧率按主要素材定，交付帧率等于时间线帧率。参考：24 偏电影感，25 国内广电，30 网络常用，60 运动画面。高帧率素材放进低帧率时间线用于慢放（见 `beat-and-speed.md`）。
- 脚本：能。
- 检查：交付帧率 = 时间线帧率；播放没有忽快忽慢。
- 常见错误：交付时改帧率。
- 状态：试用
- 来源：第 5 集

### 编码与码率
- 思路：平台会再压一次，码率拉满只增加体积；编码优先兼容性。
- 用在：设置交付格式时。
- 不用在：给后期中间件（中间件用高质量编码，见 `workflow.md`）。
- 做法：MP4 或 MOV + H.264 为默认；体积确实受限、且投放设备支持时才用 H.265。码率先用 Resolve 的自动 / 推荐；手动时 1080p30 约 10–20 Mbps，4K30 约 35–50 Mbps。看预估体积是否符合平台上传限制。
- 脚本：能。
- 检查：手机和电脑都能播放；文字边缘、细纹理没有明显块状。
- 常见错误：码率拉到最高；没必要地用 H.265。
- 状态：试用
- 来源：第 5 集

### 音频参数
- 思路：时间线听着正常、导出后变小或有杂音，多半是参数问题。
- 用在：交付时。
- 不用在：无。
- 做法：AAC 256–320 kbps，采样率 48 kHz；不用 PCM 直接发布（体积过大）。导出后回听成片并按 `finishing.md` 测响度。
- 脚本：能。
- 检查：成片声音和时间线一致，没有断音、杂音。
- 常见错误：只听时间线就交付。
- 状态：试用
- 来源：第 5 集

### AI 放大和补帧只救单段
- 思路：算法补出来的像素和帧放大后会露馅，只能用来救个别素材。
- 用在：某一段素材分辨率或帧率明显低于其他素材，又无可替代时。
- 不用在：整片；证明类镜头（会生成原本没有的细节）。
- 做法：对该片段用 Super Scale（Clip Attributes 或 Media Pool 片段属性）；补帧见 `beat-and-speed.md`。处理后放大检查。
- 脚本：部分。
- 检查：边缘没有涂抹、怪纹、过度平滑的「油腻」感。
- 常见错误：以为能真正提升清晰度；30 帧整片补成 60 帧。
- 状态：试用
- 来源：第 5 集

### 封面帧不用首帧
- 思路：第一帧常是黑场或人物还没进入状态，不是最吸引人的画面。
- 用在：交付时给封面步骤推荐候选帧。封面的制作和标题走平台封面步骤。
- 不用在：无。
- 做法：在全片里挑 2–3 个候选：主体清楚、表情自然或最能代表内容、缩成小图仍看得清。用时间线标记（`AddMarker`，备注「封面候选」）标出来。
- 脚本：部分。候选需看画面判断；标记能脚本。
- 检查：候选不是黑场或过渡帧；缩小后主体清楚。
- 常见错误：直接用默认首帧。
- 状态：试用
- 来源：第 5 集
