# 镜头组接、口播精剪、多机位、转场

先读 `choose.md`。

### 景别递进开场
- 思路：从远到近，先交代空间，再落到人物或产品细节，视线被一步步收紧。
- 用在：无配音或配音少的开场、新场景的第一组镜头。
- 不用在：开场已用 edit-combos 的 Hook reveal 直接给主体时；连续每段都用（会单调）。
- 做法：大远景（氛围）→ 中景（人和环境关系）→ 特写（情绪或产品关键细节），硬切；音乐前奏段挑平稳、没有剧烈位移的镜头，切点落在节拍标记上。
- 脚本：能。按导演稿顺序追加。
- 检查：画面从广到具体，没有跳回大景。
- 常见错误：每个段落都套同一个递进。
- 状态：试用
- 来源：第 3 集

### 匹配剪辑：形状或运动接上
- 思路：前后两个镜头有相似的形状或同方向的运动，接点处看起来像同一个东西在继续动。
- 用在：素材里确实有两个形状相似、或运动方向一致的镜头；产品外形、旋转、推近的衔接。
- 不用在：找不到真正相似的两个镜头时（不要硬凑，也不要靠转场冒充）。
- 做法：找出两个镜头里形状重合或运动同向的帧 → 硬切在这一帧；需要时用 Inspector 的 Position / Zoom 微调，让主体在两个镜头里落在同一位置。
- 脚本：部分。切点帧需人工判断；位置对齐可用 `SetProperty("Pan"/"Tilt"/"ZoomX")`。
- 检查：接点处主体位置和运动连续，没有跳一下。
- 常见错误：形状只是勉强相似；主体位置对不上。
- 变体（试用）：圆形光圈对位。前一镜里的圆形元素（按钮、表盘、杯口）在切点处和后一镜的圆形主体对齐，用圆形遮罩从这个圆心张开或收拢（6–10 帧）完成交接。
- 状态：试用
- 来源：第 3 集；video-shotcraft（circle-match-iris）2026-10-28

### 并置产生含义（库里肖夫）
- 思路：两个无关的镜头硬切在一起，观众会自己补出关系，比解释更有力。
- 用在：表现人物看到了什么、想到了什么；制造意外感。
- 不用在：需要准确传递事实的说明段（容易被误读）。
- 做法：一个动作或场景镜头 → 硬切到人物平静的面部或眼睛特写，中间不加任何解释性画面。
- 脚本：能（普通硬切）。
- 检查：观众能自然读出两者的关系。
- 常见错误：中间又插了说明镜头，把联想打断。
- 状态：试用
- 来源：第 3 集

### 声音先入画面（J-cut）
- 思路：下一个场景的声音先响 1–3 秒，画面再进来，切换就不生硬。
- 用在：进入新场景、黑场之后进画面、段落开头。
- 不用在：配音正在说话的地方（环境声会和配音打架）。
- 做法：把下一场景的环境声（海浪、街声、机器声）起点放在画面入点前 2–3 秒，加 0.5–1 秒淡入（`TimelineItem.SetFades` 以帧计）。环境声要和画面空间一致。
- 脚本：能。音频片段的起始帧 = 画面入点帧 − 提前量。
- 检查：画面出现前声音已经在；声音和画面是同一个地方。
- 常见错误：随手加不相干的音效；环境声盖过配音。
- 状态：试用
- 来源：第 4 集

### 后期推镜
- 思路：固定机位素材也能做出推近，把注意力从全景引到主体。
- 用在：主体在画面里偏小、需要强调某个细节时；素材分辨率高于时间线（推近后不糊）。
- 不用在：素材分辨率等于时间线且要推近超过约 120% 时（会糊）；已经用素材卡片缓推的镜头（见 craft-ae `components.md`，那是 100→104% 的呼吸感，不是强调）。
- 做法：简单推近用 Dynamic Zoom（`SetProperty("DynamicZoomEnabled", True)`，`DynamicZoomEase` 选 In and Out）；需要推向画面某处时，在 Inspector 同一帧给 Zoom 和 Position 同时打起止关键帧，两者同起同止并用相同缓动。
- 脚本：部分。Dynamic Zoom 能脚本开启；起止框位置和关键帧需在 Inspector 中完成。
- 检查：主体一边变大一边移向画面中心；终点构图正确；画质可接受。
- 常见错误：只给缩放打关键帧，结果原地放大；缩放和位置不同时结束。
- 变体（试用）：急推。全景先静止约 1 秒让人看清全局，然后 6 帧急推到目标（缩放约 1→2.3，位置同步收向目标中心，缓入），过冲后 5 帧回收约 4%，然后钉死不动；急推那几帧加短促的运动模糊。一次性重音，一条片最多一两次。
- 状态：试用
- 来源：第 6 集；video-talkcraft、video-shotcraft（crash-zoom-punch）2026-10-28

### 口播精剪：去停顿、留好气口
- 思路：去掉卡顿、重复和长停顿，但保留让句子能呼吸的气口。
- 用在：口播、采访素材的第一遍精剪。
- 不用在：平台流程里配音由 TTS 生成、本来没有停顿时。
- 做法：素材先转录（`MediaPoolItem.TranscribeAudio`）→ 在 Edit 页的文字剪辑里删掉多余的字句和长停顿，或对选中片段用「删除静音」；对照波形复查。句间留约 0.2–0.4 秒气口。
- 脚本：部分。转录能脚本；删字在 Resolve 界面完成，或按转录的词时间戳算切点后用 `DeleteClips(..., rippleDelete=True)`。
- 检查：听不到长停顿、重复半句、口癖；句子之间不急促。
- 常见错误：自动删得太狠，把好气口也删了。
- 状态：试用
- 来源：第 2 集

### 放大遮跳切
- 思路：剪掉口误后人物会跳一下；切点一侧放大 10–20%，看起来像换了一个机位。
- 用在：同一机位口播、跳切处没有 B-roll 可盖时。
- 不用在：有 B-roll 可以盖住时（优先盖 B-roll）；素材放大后画质明显下降时。
- 做法：切点后一段 `SetProperty("ZoomX"/"ZoomY", 1.15)`（ZoomGang 打开），必要时调 Pan/Tilt 保持人物构图；连续多个跳切时，原尺寸和放大交替。
- 脚本：能。
- 检查：看起来像两个机位；人物构图不跳；画质可接受。
- 常见错误：放大太少（像抖了一下）或太多（像另一种画面）。
- 变体（试用）：三级跳切。同一句话里需要逐步加强语气时，连续三个切点分别放大到约 110%、125%、140%，最后一级落在重音词上；之后回到原尺寸。一条片最多一次。
- 状态：试用
- 来源：第 2 集；video-shotcraft（rhythm-interrupt-moves）2026-10-28

### 多机位：先同步，再跟着说话的人切
- 思路：先把各机位同步到同一时间，再像导播一样按谁在说话来切。
- 用在：采访、对谈、多机位口播。
- 不用在：单机位素材。
- 做法：
  1. 同步：`MediaPool.CreateMulticamClip`，`angleSyncMode` 用 `MULTICAM_ANGLE_SYNC_AUDIO`（有统一时码时用 TIMECODE）。
  2. 切换：Edit 页 Multicam 查看器播放时点选机位；切错的一段选中后直接换机位。
  3. 规则：说话人开口那一帧给说话人；对方说到关键内容时切听者的反应；反应之后切回说话人。
- 脚本：部分。同步能脚本；切换需人工，或按转录的说话人检测（`TranscribeAudio(useSpeakerDetection=True)`）生成切点建议。
- 检查：各机位口型同步；画面上的人始终是在说话或在反应的人；切点处没有黑帧。
- 常见错误：未同步就开剪；声音在说 A，画面停在 B 很久。
- 状态：试用
- 来源：第 12 集

### 转场只放关键点
- 思路：转场是调味，大多数地方硬切最干净。
- 用在：段落或场景的大转折，一条片一般不超过两三处。
- 不用在：同一段落内的镜头之间；递进硬切段（见 `structure.md`）。
- 做法：优先 Cross Dissolve 或短的光效类转场，时长约 0.5–1 秒；同一条片子只用一种风格。
- 脚本：部分。转场需在 Edit 页添加；可用场景检测后人工确认位置。
- 检查：转场没有盖过内容，切换仍然流畅。
- 常见错误：每个剪辑点都加；一条片用好几种转场。
- 状态：试用
- 来源：第 3 集
