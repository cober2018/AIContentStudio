# 结构与全片节奏

先读 `choose.md` 决定要不要用；这里只写怎么用。每节格式：思路 / 用在 / 不用在 / 做法 / 脚本 / 检查 / 常见错误 / 状态 / 来源。来源指影视飓风《剪辑全能必修课》集数，内容为平台自己的归纳。

### 开场三步：提问 → 揭题 → 预告
- 思路：先让观众在心里回答一个问题，再告诉他这条片要做什么，最后用几秒高光让他相信后面更好看。
- 用在：体验、挑战、测评、信息型片子的前 10–15 秒；导演稿第一个镜头任务是「开场钩子」。
- 不用在：短于 30 秒的片子（只留一句提问或直接用 edit-combos 的 Hook reveal）；没有足够好的高光画面时不做预告段。
- 做法：配音稿先写 2–3 个观众自己关心的短问题 → 一句揭题 → 3–6 个最强画面的快切预告（每个 0.5–1 秒，切在音乐重拍上，音乐向上走）→ 回到正文顺叙。预告只给过程不给结论。
- 脚本：部分。预告镜头的选取和顺序在导演稿里定；装配按帧数追加即可。
- 检查：15 秒内说清要做什么；预告里没有提前说出结论；问题能被一眼看懂。
- 常见错误：预告把结果剧透完；问题太抽象，观众答不上来。
- 状态：试用
- 来源：第 13 集

### 时钟检查：四个节点都要有刺激
- 思路：观众最容易离开的地方大致在片长的 0、1/4、1/2、3/4 处，每处都放一个新的信息或情绪点。
- 用在：60 秒以上的片子，导演稿定稿前检查结构；拆别人的片子时也用它记录节点。
- 不用在：30 秒以内的短片（用「镜头时长按信息量」就够）。
- 做法：用总时长算出四个时间点 → 在导演稿镜头表上标出落在这些时间附近的镜头 → 每个点写出「观众为什么继续看」（新数据、反转、实测结果、冲突）。写不出就调换镜头顺序，或缩短全片，换一个更小的钟。
- 脚本：能。按镜头时长累加即可算出各节点落在哪个镜头。
- 检查：四个节点都有明确刺激；刺激点没有全挤在后半段。
- 常见错误：开头热闹，中段十几秒平铺直叙；所有好内容堆在中点。
- 状态：试用
- 来源：第 13 集

### 波峰节奏：平 → 拉起 → 回落
- 思路：一直高强度等于没有高潮。让强度起伏，并且越往后切得越快。
- 用在：2 分钟以上、内容多的片子；中段容易变平的讲解。
- 不用在：单一卖点的 15–30 秒产品短片。
- 做法：大约每 1/10 片长安排一个峰；峰的来源轮换（数据变化、实测结果、情绪反应、反转）；后段平均镜头时长不长于前段；必须保留又偏静的段落（采访、长解释）用素材卡片、关键词、图解托住（见 craft-ae `components.md`）。
- 脚本：部分。可统计前后段平均镜头时长做检查。
- 检查：能指出每个峰；后段切镜频率不低于前段。
- 常见错误：全片同一强度；结尾前反而放慢。
- 状态：试用
- 来源：第 13 集

### 镜头时长按信息量定
- 思路：一个镜头停留到观众刚好看完它的信息为止。
- 用在：所有硬切讲解；决定每个镜头时长时。与 craft-ae `components.md`「镜头 2–5 秒」一起用：区间给范围，信息量定区间内的具体值。
- 不用在：音乐卡点段（由节拍定）；配音已决定节奏的镜头（配音优先）。
- 做法：数画面里要读的东西（主体、动作、文字、数字）。只有一个主体约 1–1.5 秒；加一行字约 2 秒；有价格或多项信息约 3 秒；带运镜的收束镜头可到 4 秒左右。画面文字主次分明：核心信息大、次要信息小。
- 脚本：部分。可按镜头里的文字字数估算下限。
- 检查：切走时信息已读完，不需要回看；没有「信息多却一闪而过」或「信息少却拖很久」。
- 常见错误：所有镜头等长；为凑节拍让信息密集的镜头太短。
- 状态：试用
- 来源：第 10 集

### 递进硬切：每段只升一档
- 思路：同一个人、同一个动作，只让一个变量逐段升级，观众会自己追着看下一档。
- 用在：价格递进、装备递增、版本对比、进度升级。
- 不用在：各段之间没有同一个可比较的变量时。
- 做法：全部硬切，不加转场；每段只改变一个核心变量，且比上一段高一档；去掉会分散注意力的元素，必要时整段不用音乐，只留现场声和关键数字。
- 脚本：部分。装配是普通硬切；是否去掉音乐写在导演稿里。
- 检查：注意力始终在那个变量上；每段都比上一段更高。
- 常见错误：加转场打断递进；音乐抢走注意力；有一段原地踏步。
- 状态：试用
- 来源：第 10 集

### 粗剪先用音乐定段落情绪
- 思路：先用音乐把每段的情绪走向排出来，结构自然就清楚了。
- 用在：长片粗剪；段落多、情绪需要变化的片子。
- 不用在：配音驱动的短讲解（配音决定节奏，见 `finishing.md`）。
- 做法：每段挑一首情绪对应的临时音乐放在音频轨上排好 → 按音乐的情绪转折摆画面 → 结构定了再换正式音乐、精修。
- 脚本：部分。临时音乐可按段落时长裁切追加。
- 检查：段落切换处情绪明显变化；没有欢快音乐配疲惫画面。
- 常见错误：一首音乐从头铺到尾；把临时音乐直接当成片音乐。
- 状态：试用
- 来源：第 13 集

### 段落衔接：三种接法
- 思路：两段差异大时，硬切会让人看懵，要给一个过门。
- 用在：主题或场景切换处。
- 不用在：同一话题内的镜头切换。
- 做法（选一种）：
  1. 旁白承接：一句画外音补上一段背景、引出下一段，画面用下一段相关素材。
  2. 旁白收 → 音乐起：上一段用旁白讲完，旁白一停音乐立刻进，画面从音乐第一个重拍开始提速。
  3. 节拍小混剪：3–6 个与下一段相关的 B-roll 跟着音乐节拍切，2–4 秒后进入下一段正文。
- 脚本：部分。旁白和音乐的起点可按帧精确放置；选哪种写在导演稿。
- 检查：交接点没有两边都空的静默；过门不比正文抢戏；混剪镜头和下一段主题相关。
- 常见错误：旁白和音乐重叠打架；过门用了无关的好看空镜。
- 状态：试用
- 来源：第 14 集

### 快速收尾
- 思路：信息讲完就结束，告别越长，完播越差。
- 用在：所有片子的结尾。
- 不用在：无。
- 做法：最后一个信息点之后只留一句收尾（或 edit-combos 的 Closing question），几秒内结束。
- 脚本：能。检查最后一个信息镜头到片尾的时长。
- 检查：最后信息点到片尾不超过约 3 秒加一句话的时长。
- 常见错误：结尾单独做总结、感谢、长告别。
- 状态：试用
- 来源：第 13 集

### 长片分段剪再总装
- 思路：一口气从头剪到尾，前后节奏会脱节。先把每段剪成独立的小故事，再接起来。
- 用在：素材多、时间跨度长的片子（3 分钟以上）。
- 不用在：短片。
- 做法：按内容阶段分段，每段一条独立时间线，每段都按「在做什么 → 状态如何 → 发生了什么 → 结果变化」组织；无聊但必要的内容用旁白压缩；各段剪好后装到总时间线。
- 脚本：部分。每段可作为独立 Resolve 时间线，再按顺序追加进总时间线。
- 检查：每段单独看也成立；各段信息密度相近；每段结尾把人推向下一段。
- 常见错误：段与段之间密度差太多；必要但无聊的内容原样保留。
- 状态：试用
- 来源：第 13 集
