# 第三方剪辑的文件放在项目文件夹里，原地使用、原地登记

## 为什么

第三方模型通过 MCP 剪辑时，平台把任务文件夹建在自己的开发目录里，第三方模型没有那里的权限就交不回小样；同一个小样被复制三份，临时渲染也不清理，14 个任务已占 7.5 GB。平台只在本机用，素材应直接用原文件，结果导出一次就登记。详见 findings.md。

## 改什么

1. **固定工作位置**：每个项目文件夹加 `工作/`，每条作品每次剪辑一个子文件夹 `工作/<作品>/任务<N>/`，第三方模型的临时渲染、AE 单镜头渲染、达芬奇 / AE 工程都放这里。不再用平台开发目录里的任务文件夹。
2. **素材直接用原文件**：「准备素材」改成返回每条素材在硬盘上的原始路径（只读使用），不再复制或链接到别处。平台记下素材的指纹，交付时核对素材没被改过。
3. **结果导出一次就登记**：小样导出到 `导出/小样/`，成片导出到 `导出/成片/`，其他交付文件（字幕、工程、剪辑清单、AE 中间片）放在本次的 `工作/…/任务<N>/`。第三方模型用「交付结果」告诉平台文件路径，平台原地检查格式、时长、响度和指纹后登记，不复制。成片通过时，原地登记为素材，不再搬动。
4. **代理素材开关**（设置里，默认关）：打开后，平台给大视频素材生成低清代理，放在 `工作/代理/`，同一素材只做一次；「准备素材」同时给原片路径和代理路径，剪辑用代理、导出用原片。
5. **自动清理**：新一版小样交回后，旧版本任务的 `工作/` 临时文件删掉（已交付登记的文件保留）；成片通过后，这条作品的 `工作/` 只留本次成片对应的工程文件，其余删掉。
6. **旧文件处理**：现有 `.creative-executions` 里的 7.5 GB 先列清单给用户看，用户确认后再删；仍要用的（当前待看的小样 83、84）先登记到项目文件夹再删旧的。
7. **交付失败留痕**：MCP 工具出错时记录工具名、任务号和错误码（不记密钥），方便查交不回来的原因。

## 不做

- 不改三处停等用户（导演稿、小样、成片）和页面上的审片流程。
- 不改素材的权限规则（哪些能给模型用、能否公开）。
- 第三方模型对移动硬盘的访问权限由用户在那边开，平台只在说明里写清需要的路径。
