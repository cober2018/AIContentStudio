# 发现（2026-10-29 实查）

## 现在的交接链路
1. `prepare_video_edit` 开剪辑任务 → 平台在 `apps/api/app/media/.creative-executions/<用户>/<任务>/` 建私有文件夹（只有平台账户可读写，0700）。
2. `materialize_inputs`：外部素材链接原文件；库里的素材做系统级复制（同盘 APFS 不多占）。`inputs/` 实测 976K，这一步基本不浪费。
3. 第三方模型必须把导出写进任务文件夹的 `outputs/`，再逐个 `submit_output`。
4. `submit_output` 把文件完整复制到 `staging/<hash>.bin`（与 outputs 内容相同、不同文件）。
5. 收齐后 `after_execution` 再复制一份到 `<项目>/导出/小样/`。
6. 成片通过时 `decide_output` 从 staging 复制进素材存储，再移到 `<项目>/导出/成片/`。

## 问题
- 任务文件夹在平台开发目录里；第三方模型若在自己的目录起任务、没有平台目录权限，就写不进 outputs，小样交不回来。
- 同一个小样最多 3 份（outputs、staging、导出/小样），成片再多一份。
- 第三方模型的临时渲染（work/、ae/）也落在任务文件夹，任务结束不清理。14 个任务共 7.5 GB；海底光缆留了 5 次任务，每次约 1 GB。
- MCP 工具报错以 HTTP 200 的结果返回，日志不记工具名和错误码，交付失败查不到原因。
- 现在 83、84 两条的小样已交回（任务 11、14 都是「小样待你看」）。

## 关键决策
- 用户 2026-10-29 选定：固定工作位置放在每个项目的文件夹里（`/Volumes/T1000/自媒体素材/<项目>/工作/`）。
- 代理素材参照剪映：一个开关，默认关。

## 实施时的决定（2026-10-29）
- 新流程只用于第三方模型剪辑（执行者 `codex-video-production` + 包 `director.video.v1`）。人工网页视频、ChatGPT 人工生图和通用外部执行者仍走平台私有传输（上传落 staging），它们有实际用途，保留；剪辑专用的旧路（复制到 `导出/小样` 的 `export_copy` / `sample_copy`）删除。
- 不加数据库列：项目文件夹里的交付文件，绝对路径直接记在 `CreativeExecutionOutput.staging_key`（以 `/` 开头即项目文件，否则是私有传输键）。原列 500 字符够用，省掉一次迁移和对旧库的结构检查。
- 通过时按素材盘登记文件的现成方式（`external/<素材盘>/<指纹>/<相对路径>` 键）原地登记，不进素材存储、不搬动；页面、库、预览都按这个键找到原文件。
- 剪辑清单的素材从 `inputs/<版本>-<指纹>.<后缀>` 改为 `path`（原始绝对路径）；绑定靠版本号和指纹，路径只作记录，素材之后被归档移动也不影响。
- 交付路径检查：主片只能在本项目 `导出/小样`（小样任务）或 `导出/成片`（成片任务），其他角色只能在本次 `工作/<作品>-<作品号>/任务N/`；规范化后不许 `..`，真实路径必须等于字面路径（任何一层快捷方式都拒绝），文件本身不能是快捷方式、硬链接数为 1。
- 交付后文件被改：审片播放、读取、通过时都重算指纹，不符报「文件已变化，请重新交付」（`video_chain_output_changed`）。
- 清理：新小样交回时，只删同一作品编号更小的 `任务N/` 里没被登记的文件；成片通过时同一作品其他 `任务N/` 里没登记的文件也删掉；已登记的文件一律保留（否则素材记录会指向不存在的文件）；不碰 `导出/`、`工作/代理/` 和用户自己放的文件夹；快捷方式只删链接本身。
- 代理开关存在「存储位置」同一设置里（`edit_proxy_enabled`，默认关），设置页「存储位置」下新增一块。触发条件：视频长边 > 1920 或码率 > 20 Mbps；ffmpeg 转 720p H.264，按素材指纹命名，先写临时名再改名，已存在就复用。
- 旧任务改指：素材盘和 Mac 是两块盘，「移动」等于复制 + 删除；按「旧文件夹一律不删」的要求，改成复制到项目文件夹、核对指纹后改指，旧文件留着等用户决定。
