## Why
量化研究专家想每天发一篇复盘文章，持续追踪市场：即使没有别的选题，每天也有内容。数据来自数据中台的复盘服务，但其中有投资建议类内容不能对外展示。现有「DreamO 量化平台（生产）」连接拉的 4 个看板里，行业复盘×生命周期、行业 RRG 轨迹正是这类内容，而且 4 个里 3 个在拉取失败；这些数据只进项目事实，没接到量化研究专家的选题。

## What Changes
1. **数据来源**：按 DreamOAgents/docs/api/public-dashboard-data-api.md，接数据中台公开看板服务（public-market-participation、public-market-index-position、public-market-compensation、public-market-short-feedback、public-industry-review；public-forward-risk-events 有权限时自动加宏观日历）。2026-11-11 由 review-* 改为 public-*：本平台的 Key 只开通了 public-*。
   - 用本平台单独的 API Key（新环境变量，只放服务端），不和模拟项目共用；没配 Key 时不跑，数据保障提示「缺少数据中台密钥」。
   - 停掉旧连接的「行业复盘×生命周期」「行业 RRG 轨迹」两项拉取。
2. **合规过滤（只留白名单字段）**：每个服务只保留文档列出的事实类字段（涨跌幅、成交额、资金流、广度、相对强度数值、情绪指标、事件日历、连板梯队、涨跌停计数、开盘统计）；生命周期阶段、主攻标签、信号优先级、拥挤度、RRG 象限判断、领涨股、题材阶段与强度分、风格信号、操作指引、预测状态一律不进平台。统一单位（成交额换成亿元，涨跌幅统一成百分数）。事件日历只留未来几天的宏观事件，去掉占位数据。
3. **项目结构**：
   - 量化研究专家下建一个长期项目「每日复盘」，和一个属于该角色的栏目「每日复盘」。
   - 每个交易日一篇文字作品（如「2026-11-10 复盘」），挂在这个项目和栏目下，当天过滤后的数据作为作品的事实资料。
4. **每日流程**：每天 07:30 取上一交易日数据（数据中台 21:00–次日 02:00 生成）；当天没数据（非交易日）就跳过不建作品。建作品 → 平台出关键图表 → 平台模型按事实写文章初稿（文章里插图表）→ 停在「稿子」等你采用或写意见 → 之后照常审阅与交付，不自动发布。
5. **图表**：用平台本地出图工具把关键数据画成图片放进素材库，文章用图片插入（文字作品没有表格块，表格也出成图）：
   - 大盘环境表（指数涨跌、全市场涨跌家数、成交额）
   - 行业涨幅居前、跌幅居前（上游榜单各 5 个）
   - 行业资金净流入、净流出前各 5
   - 连板梯队与涨跌停计数
   - 情绪关键指标表（ERP、估值、参与度、封板率等）
   - 未来几天宏观事件表
6. **数据保障**：每日复盘纳入巡检：数据中台取不到、出图或写稿失败都自动重试，补救不了在内容机会页提醒。

## 不做
- 不自动发布、不自动推送公众号。
- 不做视频或图文卡片版。
- 不用旧连接的生命周期、RRG 象限等建议类数据，也不在文章里写买卖建议。
- 不改其他角色的选题流程。

## Impact
新增每日复盘服务（取数、白名单过滤、单位换算、出图、建作品、写初稿）和定时任务；数据接入里新增连接与端点、停用旧连接两项；数据保障加一项检查。复用现有项目 / 栏目 / 文字作品 / 本地出图 / 平台写稿流程，不改数据库结构（如需新字段在实现前说明）。

## 变更四（2026-11-16）：每日复盘改成 MCP，停掉平台自动调度
用户 11-16：「这个功能可不可以做成 MCP，不要做在平台上的自动调度。这个功能我打算用 Antigravity 来使用 Gemini 模型来写稿子……平台的话用 Grok 4.7……也可以不用平台，用第三方的。」
起因：平台默认写稿模型 gemini-3.8-flash-high 已不在 CPA 代理里；grok-4.7 写一篇要 215 秒，超过平台 120 秒上限。

| 项 | 现在 | 改成 |
|---|---|---|
| 调度 | worker 每 30 分钟检查，7:30 后自动取数、出图、平台模型写稿；有意见自动重写 | 去掉定时任务和自动重写；数据保障里「每日复盘」一行一起去掉 |
| 取数、出图、建作品 | 定时任务里做 | 新 MCP 工具 `prepare_daily_review`：不传日期就取最近一个已完成的交易日；建（或找到）当天作品、取数、出图（同一天再调用复用已出的图）；返回作品编号、事实、图表清单（key、标题、说明、素材编号）、写稿规则和 text.master.v2 格式示例。放进 MCP 设置里「写文章」那一组 |
| 写稿 | 平台模型 | 第三方模型（Antigravity 里的 Gemini、Claude Code 等）用现有的 `save_article_draft` 存稿；用户在页面上采用或写意见，模型用 `get_article_decision` 读意见再改 |
| 存稿检查 | 平台写稿时查投资建议用语 | 每日复盘作品存稿时同样查，出现买卖、仓位、推荐之类的词就拒绝，并说明是哪个词 |
| 页面 | 「每日复盘」标签 | 不变；说明改成「由第三方模型通过 MCP 写稿：在那边说『写今天的复盘』」 |
| 已有的五篇 | — | 用新工具重生成：这次由 Claude Code 作为第三方模型写，也顺便把 MCP 整条路走通 |

变更三的图表和以图为主的写稿规则不变，只是规则改成从 MCP 工具返回给第三方模型。
