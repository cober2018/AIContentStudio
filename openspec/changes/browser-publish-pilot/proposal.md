## Why
发布包（成片、封面、发布文案）都做好了，最后一步还要人逐个平台上传、填标题话题、传封面。视频号、公众号视频没有上传接口，只能在网页后台做。ego lite 浏览器（ego-browser skill）能让模型用你已登录的浏览器操作网页、上传本机文件、更省 token。分工：**Codex Desktop（桌面应用）主做这块浏览器自动化**，Claude Code 能做但只当备用。先拿一个平台试点走通。

## What Changes
- **试点平台：视频号**（没有上传接口，自动化价值最大）；用作品 97 的成片做一次「只存草稿、不发布」的演练。
- **只做到草稿 / 待发布**：模型上传成片和封面、填好描述和话题，停在「发表」之前截图；最后点「发表」由你来。登录、扫码、验证码都停下等你。
- 平台加三个 MCP 工具（Codex Desktop、Claude Code 都能用）：
  - 列出待发布的交付目标（哪个作品、发哪个平台、现在什么状态）
  - 取一个交付目标的发布包：成片、封面在硬盘上的绝对路径（只读，原文件不复制不改），以及这个平台要用的标题、描述、话题
  - 记一笔「已存成草稿」：附截图路径和说明，交付页显示「第三方模型已上传草稿，等你发布」；你发布后照旧在交付页回填链接（回填仍由你来，不代填）
- 平台新增操作说明 skill `craft-publish`（经 get_craft_skill 读，两边通用）：总则（只到草稿、每步截图、遇登录验证码停、不改发布包内容）+ 视频号一份分步说明；以后每加一个平台加一份。
- Codex Desktop 用法：在 Codex Desktop 里说「把作品 97 上传到视频号草稿」，它按 craft-publish 和 ego-browser 去做。

## 不做（试点之外）
- 其他平台（公众号视频、头条、小红书、B站、抖音等）：试点走通后逐个加。
- 自动点「发表」、自动回填回执。

## Impact
- apps/api/app/services/creative_mcp.py：三个工具与说明
- apps/api/app/services/delivery.py（或新文件）：发布包路径与文案取用、草稿记录
- craft_skills/craft-publish/：总则与视频号说明
- apps/web 交付页：显示「已上传草稿」记录
