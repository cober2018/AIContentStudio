## 3. 必须实现的用户流程

保留角色五步：选题与资料 → 内容方案 → 制作内容 → 审阅修改 → 交付。保留商品六步和两者的独立性；底层工具共用。

- 正常页面聚焦当前产物、待确认问题和下一步；方法、模型回执、技术标识、历史折叠展示，手机和键盘可用。
- 角色参考可以从既有素材/来源正常选择、预览；不用用户手填 ID/hash。支持文字、图片、音频、视频的正反例与准确定位，保留授权和精确版本。
- 通用方法与角色风格分开，保留阶段/单方法独立开关。关闭的方法在完整实际请求中不得通过嵌套快照或回退残留；配置选择和实际加载分别留痕。
- 选定知识分专业参考、风格样本、已核实事实；不读未选 Obsidian 笔记、不扩大授权、不把旧观点自动变为事实。

- 默认只改当前作品。长期偏好须明确角色/栏目/形式与规则差异，采用新修订；并发409保留草稿，不覆盖他人配置或自动重试。

旧版本、角色默认、产品绑定和历史快照保持。不得原地修改旧方法冒充新版本，不整包安装 Easel或运行其安装/网关/发布脚本。Skills提供思考和有界产物；确定性工具只消费声明参数，不声称自由文本已经改变排版器。

## 6. 执行方式

使用 OpenSpec apply 和 executing-plans；在同一 task_plan.md 用 `///` 记录实施步骤。按“基线与兼容 → 参考/输入 → 方法与产物 → 五步/反馈 → 开发验证”推进。已实现并验证的项可勾选；只有结构存在、自测未覆盖或需要真实素材的项保持未完成并说明。

有明确合同缺口时先最小修复。只有必须改变已确认业务范围、模型/权限或不可恢复数据时交回主 Agent判断；不要为常规实现细节反复向用户确认。不要启用额外开发 Agent并行改同一模块；如需拆分，先向主 Agent说明文件归属。

至少覆盖：首次使用、只读/归档、已选参考回读、旧版本读取、方法开关真实请求、原模型/音色保留、空/错误/unknown、跨角色隔离、局部反馈与失效、并发保存、手机布局、原入口/返回、商品保留回归。
