## MODIFIED Requirements

### Requirement: Auditable module coverage
The design SHALL map every current App.tsx route to a task, destination, and keep/change/compatibility decision, with evidence and explicit prototype depth. A scoped Persona method refinement SHALL reuse the established role five-step shell and existing entry/return contracts; it SHALL identify the specific child surfaces being extended without reopening the completed site-wide navigation redesign.

#### Scenario: Existing improved workflow
- **WHEN** a route belongs to the improved product six-step or persona five-step workflow
- **THEN** the design preserves the product workflow internals, Persona step identities and navigation shell, and model-configuration internals; only explicitly scoped Persona method/planning/review child surfaces can be extended

## ADDED Requirements

### Requirement: Persona production presents the current artifact and next actionable task
The five existing Persona worksteps SHALL project saved project/workflow/artifact state into topic-and-sources, content-plan, production, review and delivery tasks. Each view SHALL prioritize its current artifact, unresolved questions and one primary next action, with detailed methods, inputs, model receipts and history available on demand. Empty, unreadable, failed, unknown and unaccepted results MUST NOT appear completed. Navigation and preview MUST NOT generate, accept, save or publish content.

#### Scenario: Continue a partially completed graphic work
- **WHEN** a user returns from the work list to a Persona Graphic work with an accepted card plan but no accepted rendered images
- **THEN** the saved plan is shown with the pending render/review action, the work remains incomplete, and the list filter, page and workstep return context is retained

#### Scenario: Browse on a narrow screen
- **WHEN** a user opens the role worksteps on a phone-width viewport or by keyboard
- **THEN** artifact preview and actions remain usable without new page-wide horizontal overflow, and advanced metadata is not required to understand the next task

### Requirement: Local creative feedback does not require fabricated publication
Persona result feedback SHALL be available through the existing stage/work review path before public publication. It SHALL bind to that exact result and remain distinct from the existing published-performance observation path. Missing audience metrics MUST remain missing.

#### Scenario: Give feedback after a local ZIP delivery
- **WHEN** a user comments that a locally delivered image is too dense
- **THEN** the work-stage feedback records the image/version/location without creating a published-content record or zero-valued performance metrics
