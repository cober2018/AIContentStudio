## Why

用户 2026-11-27 的要求（看完 11 月线上数据复盘后）：

- 每个选题先有一份**本体**，本体就是**全文**（一篇完整文章）。其他内容都从本体加工，不另起炉灶。
- 内容只分**四种形态**：长文、图卡、横版视频（16:9）、竖版视频（9:16）。每个选题四种都能做，只是选哪几种的问题。
- 流程：定了选题以后，让用户勾要做的形态，后面自动生成。
- **不按平台分版本。**各平台对好内容的要求差不多，写作标准要沉淀成我们自己的一套。按平台分会让一份本体变出太多版本，太复杂。

这次复盘里各平台的经验其实是同几条，正好说明不必分平台：
- 第一句就给矛盾，前几秒让人知道要解决哪件事；
- 给一张能保存、下次还能照着用的图或表；
- 公式落到能逐行核对的表上，并写清适用条件。

## 现状（2026-11-27 查过代码和库）

- **选题转项目时不建作品。**`POST /content-opportunities/{id}/convert-to-project`（`routers/opportunities.py:378-547`）只建项目和简报。形态建议只读显示，页面写着「不会自动建立创作单元」（`OpportunityPages.tsx:359`）。转完跳到 `?next=creation`，但没有代码读这个参数。
- **作品要一条条手动加。**空项目问「这个项目要做什么？」（`PersistentProjectPage.tsx:207`），新增作品一次选一个形态（文字 / 图文 / 视频）。内容矩阵 tab 能多选，但视频只有 `douyin/spoken_script` 一种，分不出横竖（`ProjectMatrixTab.tsx`）。
- **没有本体这个概念，也没有任何血缘字段。**
  - 视频和文章的写作简报里的 `source_texts`，只是把同项目其他文字作品的最新版拍平、截到 8000 字（`video_chain.py:695-699`，`article_chain.py:240-244`），没记用的是哪一版。
  - `ContentMasterRevision` 只有同作品内的 `parent_revision_id`；渠道版本的 `source_master_revision_id` 也必须是同一作品（`channel_variants.py:918-920`）。
- **已发表文章改视频时，文章本身没进平台。**作品 95–148 都是这样：文章只写在简报目标和导演稿备注里，正文、原图出处都没登记成来源。
- **横竖只存在视频母版里。**`video.master.v2.payload.aspect_ratio` 由第三方模型在导演稿里自己填，作品上没有横竖。9:16 和 16:9 从头到尾都能做：AE 模板原生 9:16、多数有 16:9 版本，剪辑分辨率、片头片尾、封面都按比例分开。
- **搜索推广工作台已经有一半。**它能勾形式（文 / 图 / 视），先写「核心稿」，图文和视频由核心稿衍生；项目不含文章时，核心稿只作底稿（spec `search-promotion-workbench`「Core text, derived works and writing rules」，`search_promotion.py:550-586`）。但它也只在 `search_work.role` 里记了 core / derived，没记从核心稿哪一版来。它只在 search 域可用，视频也分不出横竖。
- **平台差异现在已经很薄。**
  - 成片本来就是一个候选授权给多个平台发（`finished_video.VIDEO_CHANNELS`：抖音、小红书、视频号、B站……）。
  - 发布文案每个作品一份，不按平台分（`publish_copy.py:61`）。
  - 图文到小红书、B站图文、公众号图片消息是机械映射（`GraphicImageNoteAdapter`）。

## What Changes

### 1. 本体：每个项目一份全文

- 项目里有且只有一份本体，形态是文字（`text.master.v2`），作品上标「本体」。它沿用现有文字作品的版本、事实边界和审稿机制，不新建一套存储。
- 本体要写清这几块，存成结构化的段落，方便派生时按块取：
  - 要回答的问题；
  - 结论（开头就说）；
  - 做法或口径（样本、区间、定义、纳入规则）；
  - 结果表或算例（能逐行核对）；
  - 适用条件和不适用的情况；
  - 素材与数据出处（每条有来源、取数日期，区分「自家使用经验」和「供应商当前承诺」）。
- 本体有两种来源：
  1. **新写**：第三方模型或平台模型按选题写全文。
  2. **用已发表的文章**：用户选一篇已发表文章（发布记录或文章文件），平台把正文、原图、发表链接登记成本体的第一版，来源记成「已发表文章导入」。
- 新写的本体定稿要用户看一次（「本体待你看」）。所有数字和结论都从这里来，这一处值得停。
  - 不管是第三方模型还是平台模型写的，全文都 MUST 存进平台、在平台页面上完整展示，用户在页面上确认后才进入下一步。第三方模型不能只在对话里给出全文。
  - 已发表文章导入的本体，用户在建项目时亲自选了它，就算定稿，不再停。

### 2. 定选题后勾形态

- 选题转项目、新建项目、空项目页，统一加一步「要做哪几种」，四个勾选框：**长文、图卡、横版视频、竖版视频**。同一步选本体来源（新写 / 用已发表文章）。
- 角色可以设默认勾选（「量化研究专家」默认长文 + 图卡 + 横版视频），用户每次可改。
- 项目建好后还能随时补勾或取消某种形态。取消只针对还没开始的形态，已开始的作品照现有规则归档。

#### 勾选在流程里的时机

勾选分两次给用户看，但不新增停点：

| 时机 | 用户看到什么 | 勾选的效果 |
|---|---|---|
| ① 建项目（选题转项目 / 新建 / 空项目页 / MCP `create_project`） | 四个框，按角色默认预先勾好 | 建出对应作品，状态「等本体定稿」，不开工 |
| ② 本体待你看（仅新写本体） | 全文 + 同样四个框，带着①的勾选 | 用户读完全文再改勾选；点「定稿」时以这一刻的勾选为准开工。新勾的建作品，取消的删掉（都还没开始） |
| ③ 定稿以后任何时候 | 项目页本体卡片上的四个框 | 补勾：从当前定稿本体新建并开工；取消：只能取消未开始的 |

- 「竖版按题目再勾」落在②：竖版只追一个点，读完全文才知道有没有一个点值得单独做 1 分钟。用户在建项目时不用想竖版，定稿时顺手勾。
- 导入的本体没有②，建项目时的勾选就是开工的勾选；之后想加竖版走③。
- MCP 建项目时不传形态就用角色默认；第三方模型不能在②替用户改勾选，勾选只能由用户在页面上改（或用户明确让它在 `create_project` 时传）。
- MCP 的 `create_project` 同样接受「形态」和「本体来源」两个参数，第三方模型建项目时和页面效果一样。

### 3. 四种形态是作品上的固定属性

| 形态 | 作品 | 从本体取什么 | 规格（默认，可在设置里改） | 可发的平台 |
|---|---|---|---|---|
| 长文 | 就是本体本身 | 全文 | 不另写一篇；本体定稿后直接出平台版本 | 公众号、知乎、头条等现有文字平台 |
| 图卡 | 图文作品 | 问题、结果表、判断步骤、结论 | 3～6 张，3:4；首张放问题，中间放表，末张揭晓或给可勾选清单 | 小红书、B站图文、公众号图片消息 |
| 横版视频 | 视频作品，16:9 | 完整过程：问题 → 做法 → 结果怎么核 → 结论 | 3～5 分钟 | B站、YouTube、公众号、视频号等 |
| 竖版视频 | 视频作品，9:16 | 只追一个点 | 约 1 分钟 | 视频号、抖音、小红书视频等 |

- 形态（含横竖）记在作品上，建好后不能改。要换比例就新开一个形态作品，从同一本体派生，不从横版裁成竖版。
- 视频导演稿的 `aspect_ratio` MUST 与作品形态一致，不一致存不进去。
- 长文不另建作品：本体定稿后按现有文字平台版本机制出公众号等版本。这和搜索推广「核心稿」的规则一致。

### 4. 派生和血缘

- 每个形态作品的母版版本 MUST 记录它从**本体哪一版**派生：新增字段，例如 `source_body_revision_id`。写作简报给的是这一版本体的结构化内容，不再是拍平截断的 `source_texts`。
- **一致性检查**（存稿时平台自动做，不过关不让存，并返回具体哪条不对）：
  - 派生稿里出现的数字、日期、样本区间、公式，必须能在本体或已冻结事实里找到；
  - 结论不能和本体相反，也不能比本体更强（本体写「样本无法区分」，派生稿不能写「B 更好」）；
  - 节选要标「节选」，示例结果和全样本结果不能混说。
- **本体改了以后**，已派生的作品显示「本体已更新到第 N 版」，列出改了哪几块，由用户决定哪个形态按新本体重做。平台 MUST NOT 自动覆盖已开始的作品。素材已通过的视频照现有规则：换素材会开新任务。
- 页面上，从本体能看到它派生了哪些形态、各自用的是哪一版；从每个形态作品能点回本体那一版。

### 5. 自动生成

- 本体定稿后，勾选的形态自动开始，不用再一个个点。
  - **写作方是平台模型**：只写文字（本体、长文平台版本），后台按顺序写，沿用搜索推广后台执行的做法（失败可单步重试，每步记模型和结果）。图卡和视频即使写作方选了平台模型，也进入「等第三方模型」。
  - **写作方是第三方模型**：作品进入「等第三方模型」，MCP 能一次列出所有待做的形态作品（含本体版本和形态规格），第三方模型接手做。
- 人工停点不增加，沿用现有链条：
  - 本体：本体待你看（新增，见第 1 条）；
  - 长文：平台版本照现有方式审；
  - 图卡：稿件待你看、成图验收（照现有）；
  - 视频：素材（按开关）、小样、成片（照现有）。
- 平台 MUST NOT 提供替用户通过本体、稿件、成片的工具（沿用现有约束）。

### 6. 统一写作标准（我们自己的一套，不分平台）

- 新增一份写作标准 skill，例如 `studio.form.writing-standard`。所有形态的写稿简报都带上它，第三方模型和平台模型都用同一份。第一版内容：
  - **开头**：第一句（视频前 5 秒）就给矛盾或冲突的两样东西，例如两根 K 线、两个日期、两个几乎一样的因子；不先讲比喻铺垫。
  - **带走物**：每篇至少有一样观众能保存、下次照着用的东西：一张图、一份表、一个能复算的例子，或一张可勾选清单。
  - **可复算**：写明样本、区间、定义、纳入和剔除规则；公式落到能逐行核对的表上。
  - **如实**：先算再定结论；样本区分不出来，就展示「区分不出来」。核不到的报价、权限、频率删掉，只留判断方法。分开写自家经验和供应商承诺。
  - **节选与示意**：为手机展示只挑几行要标「节选」；只有示意数据时标「示意」，不能据此宣称真实结果。
  - **四种形态各自怎么从本体取材**：即第 3 条的表。
- 能机械检查的项（开头是否给出问题、带走物是否存在、节选是否标注）进第 4 条的一致性检查。不能机械检查的写进 skill，由评审 skill 把关，沿用现有 `studio.video.script-review` 等。
- 以后用户给的通用写作要求，往这份标准里加，不分平台写。

### 7. 平台差异只留机械规则

- 每个形态作品一份发布文案（现有做法不变）。发到某个平台时，只按该平台的机械限制自动处理：标题字数、话题标签个数、简介长度、封面尺寸。超限时提示改哪一项，不另写一版。
- 平台的机械限制集中登记在一张表里，供发布文案和交付共用。现有分散在适配器里的上限（例如公众号图片消息标题 32 字）搬进这张表。

### 8. 搜索推广

- 搜索推广的「核心稿」就是本体，「形式」就是形态。本次让两个工作台共用同一套本体、形态、血缘机制，搜索推广补上横竖之分和血缘字段，现有搜索推广行为和两道人工关卡不变。

## 不做

- 按平台分别改写同一形态（例如 B站横版和 YouTube 横版各写一版）。
- 从横版视频自动裁成竖版，或竖版自动改横版。
- 「一份视频母版 → 多个渠道视频版本」的视频渠道适配器。按形态分后不需要。
- 新的发布方式。发布沿用现有发布目标和浏览器发布。
- 改已有作品。已存在的项目和作品不迁移成本体结构，保持原样可读。

## 用户已定（2026-11-27）

1. 新写的本体要停一次。不论第三方模型还是平台模型写的，全文都要在平台页面上展示、用户确认后才进下一步。导入的本体不停。（见第 1 条）
2. 「量化研究专家」默认勾长文 + 图卡 + 横版视频。竖版在「本体待你看」那一步读完全文再决定勾不勾，不新增停点。（见第 2 条「勾选在流程里的时机」）
3. 平台模型这次只写文字（本体、长文平台版本），和搜索推广一样；图卡和视频仍由第三方模型做。

## 验收（由 Claude Code 以用户身份试用）

开发完成后，Claude Code 不看代码，只用页面和 MCP，按用户的实际需求逐条试，并把结果写进 `progress.md`：

1. **新选题**：从一个选题转项目，勾「长文 + 图卡」，本体来源选「新写」。验证：
   - 本体写好后停在「本体待你看」，全文在页面上完整可读，勾选框带着建项目时的勾选；
   - 在这一步补勾「竖版视频」再定稿，竖版作品随之建出并开工；
   - 定稿后图卡自动进入待做，长文直接出公众号版本；
   - 中间不用再手动加作品。
2. **已发表文章**：选一篇已发表文章建项目，勾「横版视频 + 竖版视频」。验证：
   - 本体第一版就是原文，来源和发表链接可查，不停；
   - 两个视频作品各自固定 16:9 和 9:16，导演稿比例填错存不进去；
   - 两者都能点回本体那一版。
3. **一致性**：在图卡稿里故意写一个本体里没有的数字，或把「样本无法区分」写成「B 更好」。验证：存不进去，并指出是哪条。
4. **本体改版**：本体改一处结果表后，已派生作品显示「本体已更新」和改动块，不自动重做；点重做后新稿用的是新版本体。
5. **补勾**：项目建好后补勾「竖版视频」，新作品从当前定稿本体派生。
6. **第三方模型**：通过 MCP 一次列出全部待做形态作品，拿到本体结构化内容和形态规格，存稿时自动带上血缘。
7. **平台机械规则**：一个横版成片授权到 B站和视频号，标题超过某平台字数时只提示，不要求另写一版。
8. **搜索推广不回退**：照常开一个搜索推广项目，两道人工关卡和后台执行不变，核心稿和衍生作品之间也有血缘。
9. **写作标准**：任一形态的写作简报里都带写作标准 skill；同一份标准被四种形态共用。
