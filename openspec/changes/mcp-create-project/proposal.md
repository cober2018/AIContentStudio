# 第三方模型通过 MCP 新建内容项目和作品

## 为什么

现在 MCP 只能接手平台里已经建好的作品，项目和作品都要用户先在页面上建。用户希望第三方模型自己搜集选题后，直接在平台里建项目和作品，再按现有流程往下做，而不是只依靠平台每天自动出的内容机会。

## 改什么

MCP 新增 3 个工具（`creative_mcp.TOOLS`），都用现有 MCP 令牌对应的用户身份：

| 工具 | 输入 | 返回 |
| --- | --- | --- |
| `list_personas` | 无 | 未归档角色的编号、名称、定位摘要，以及可选的发布渠道 |
| `create_project` | 标题、目标、核心观点（可选）、切入角度（可选）、**选题理由（必填）**、参考链接（可选，0～10 条，每条 url + 标题） | 项目编号 |
| `create_unit` | 项目编号、角色编号、形式（video / graphic / text）、发布渠道（可选）、作品标题 | 作品编号 |

1. **建项目不选角色，建作品才选**：与页面一致。一个项目可以有多个作品，挂不同角色、不同形式。
2. **复用现有逻辑**：`create_project` 走现有的建项目，再写入第 1 版项目简报（目标、核心观点、切入角度）；`create_unit` 走现有的建作品（角色快照、默认工作流、渠道校验全部照旧）。
3. **选题理由与参考链接**：存进第 1 版简报的 `references`，标记来源为第三方模型。项目页的简报区显示「由第三方模型创建」和「选题理由」；有参考链接才显示链接，没有就不出现。
4. **建好即可往下做**：建项目不需要用户先确认；作品建好后第三方模型按现有流程从导演稿或文章开始，导演稿、小样、成片照常停下等用户审。
5. 错误沿用现有 MCP 错误格式（字段、规则、上限，不回显内容）。

## 不做

- 不改平台每天自动出的内容机会，不通过 MCP 新建内容机会。
- 不通过 MCP 建商品作品（仍走商品工作台）。
- 不通过 MCP 删除、归档或改名项目。
