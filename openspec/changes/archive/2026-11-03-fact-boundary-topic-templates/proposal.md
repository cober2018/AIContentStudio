# 事实边界自动化：按题材模板由模型找出处、平台自动核对并冻结，用户只审稿

## 为什么
事实边界（冻结的已核实事实清单）保证成片和文章里当事实说的话都有真实出处，健康类内容尤其需要。原来要用户自己去「来源与事实边界」页加来源、核对、冻结、绑定，除了海底光缆没人用过；角色作品不绑就过不了「准备剪辑」。

第一版（按模板起草、用户在页面冻结）做完后用户认为仍多一步：事实边界应由模型按平台模板自己判断、平台自动核对，用户不单独管，只审导演稿 / 文章。用户 2026-11-03 确认按这个思路改。

## 改什么

### 1. 内置 7 个题材模板（不变，内容见 design.md）
① 健康科普 ② 育儿与家庭教育 ③ 好物与产品体验 ④ 科技与 AI ⑤ 量化与投资 ⑥ 生活观察与新鲜事 ⑦ 政策与民生。存成平台内置数据。

### 2. 模板自动选
- 模型交事实时带上它按选题选的模板；项目还没选时就按它的记下。平台按选题和角色定位给建议。
- 「选题与资料」里的模板选择保留，只用来在模型选错时改；不选也不拦。

### 3. 模型交事实，平台自动核对并冻结（MCP）
- `get_fact_template`：模板全文、已选 / 建议的模板、任务书、当前事实边界。
- `submit_facts`（替代第一版的 `save_fact_draft`）：模型交这条内容要当事实说的全部话，每条带来源网址、来源原文摘句、来源日期、对应模板；引语和专家观点写谁说的。平台逐条打开来源核对：
  - **退回**（不收）：来源打不开、原文对不上。返回原因，模型换来源重交，或把这句删掉、改成个人经历的说法。
  - **收下但标注**：来源不在模板常见权威网站里、来源可能过期。
  - 收下的条目自动冻结成项目事实边界新一版（替换上一版）；一条都没收下就不动原事实边界。没有草稿、没有用户冻结这一步。
- 写作规则：先 `submit_facts`，再存导演稿 / 文章；事实改了要重存稿子（平台已有「稿子早于事实边界算过期」的规则）。资料包带模板红线。

### 4. 用户只审稿
- 导演稿审阅和文章审阅处加一行：「本稿用到的事实：N 条已核对出处（M 条来源不在常见权威网站 / 可能过期）」，可展开看每条的话、来源链接、原文摘句和标注。不用操作。
- 稿子是按旧事实边界存的，照旧提示要让第三方模型重存。

### 5. 去掉手动入口（只留新版本）
- 「来源与事实边界」页：去掉「选择已冻结 FactPack 绑定」「新建项目证据包」「克隆当前边界为草稿」「编辑 / 冻结草稿」和第一版的「冻结并启用」草稿区；改成只读的「当前事实边界」（条目、来源、标注）和历史版本，加题材模板选择。「项目来源」「知识参考」两块不动（不是事实边界）。
- 系统资料库：去掉事实包的新建、编辑、绑定到项目，只留查看。`FactPackTools.tsx` 没人用了就删。
- 后端手动接口（建事实包、加条目、冻结、克隆、项目绑定）暂留：16 个测试文件和工作流引擎靠它们建数据，这次不动，页面上不再出现。

### 6. 清理测试数据
10 个没绑任何项目的测试事实包（#1–#10）先查确实没有任何稿子、渠道版本引用，再删；改线上数据库，等用户说「上线」时做。海底光缆（#11）在用，保留。

### 不变
「准备剪辑」要冻结事实边界的把关；商品作品照旧不用事实边界；不逐句自动判断真假。

## 验收
| 项 | 怎么验 |
| --- | --- |
| 模板 | 7 个模板都能取到 |
| 自动选 | 数据库副本：项目没选模板时 `submit_facts` 带 health → 项目记下健康科普 |
| 自动核对冻结 | 数据库副本（抓网页用替身）：交 5 条（正常 / 打不开 / 对不上 / 不在常见网站且过期 / 引语）→ 2 条退回带原因，3 条收下（1 条带标注）并自动冻结成事实边界第 1 版；再交一份 → 第 2 版替换；全退回时事实边界不变 |
| 准备剪辑 | 作品 94 事实边界有了以后不再报缺事实边界，导演稿提示要重存 |
| 审稿显示 | 页面：导演稿审阅处显示「本稿用到的事实：3 条已核对出处（1 条…）」，展开有来源；「来源与事实边界」页没有手动绑定 / 新建 / 克隆 / 冻结入口，显示只读事实边界和历史 |
| 测试 | 前端类型检查通过；全量测试照旧（已知 5 个旧失败除外） |
