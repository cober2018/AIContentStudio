## Why
效果复盘现在靠用户截图，模型看图读数再导入。有了 ego lite 浏览器，模型可以直接打开已登录的平台后台读作品数据录进平台。分工：Codex Desktop 主做，Claude Code 备用。用户要求先在开发阶段自己用浏览器跑通，看平台怎么改更顺，再把做法沉淀成 MCP 里的 skill。

**发现的问题**：作品 97 已由 Codex 发到公众号、小红书、百家号、抖音，平台里有这几条发布记录，但都**没有发布时间、没有链接**，小红书那条还没挂账号。现在导入按「账号 + 标题 + 发布时间」认作品，抖音的标题又是「标题 + 正文」，所以现在导入会**另建一条重复作品**，数据挂不到我们自己的作品上，复盘就对不上哪条作品是哪次制作。

## What Changes

### 1. 导入能认出我们自己发的作品
- 新工具 `list_published_works(account_id)`：列出这个账号所在平台、平台已有的发布记录（编号、标题、发布时间、链接、平台作品编号、是我们做的还是外部作品），包括还没挂账号的。
- 导入的每行可以带：
  - `published_content_id`：模型对上了哪条就填哪条；
  - `platform_item_id`：平台上的作品编号（抖音视频号、小红书笔记号、公众号文章号）。
- 认作品的顺序：平台作品编号 → 模型给的记录编号 → 原来的「标题 + 发布时间」。第一次对上后平台记住作品编号，下次直接认出。
- 对上的记录缺发布时间、链接或账号时，用平台数据补上（标明来自平台数据页）。

### 2. 新的数据来源：平台数据页
- 来源类型加 `platform_page`：模型在已登录的平台后台直接读到的数据，checksum 用读到的原始数据算。
- 这种来源不用先给你看表等你点头：直接导入，导完报每个账号新增/更新几条和批次链接，整批可撤销。截图、复制文字、导出文件仍然先给你看。

### 3. 抖音补一个数据项
- `avg_play_ratio`（平均播放占比）：抖音后台列表直接显示，现在没收。

### 4. 做法写成 skill：`craft-review`（效果复盘）
- 总则：列账号 → 逐个平台打开后台 → 读数据 → 对作品 → 导入 → 报结果；遇登录、扫码、验证码停下请你处理；只读，不点任何改动按钮。
- 分平台说明：抖音、小红书、公众号（今天实跑过的接口路径和字段对照）；视频号等登录后再补。
- `get_craft_skill` 读 craft-* skill 不再要求带作品编号（复盘不针对某条作品）。

### 5. 改完实跑一次
- 用抖音、小红书、公众号今天的数据走完整条链路，作品 97 的数据挂到我们自己的发布记录上。
- 小红书登录的「coober」是量化研究专家那个账号（账号 14，用户 2026-11-12 确认）。

### 6. 发布后回填作品链接（用户 2026-11-12 追加）
- 现在发表后回执常常只有截图（作品 97 的四个平台都是），交付页显示「未填链接」，没有统一做法。
- craft-publish 写明：发表后去平台作品列表取这条作品的链接填进回执——抖音 `https://www.douyin.com/video/<作品编号>`、小红书 `https://www.xiaohongshu.com/explore/<笔记编号>`、公众号用发表记录里的文章链接；视频号网页上没有链接，留空。审核中或定时发布还拿不到链接时先不填，过后补。
- 新工具 `report_publish_link(target_id, link)`：给已发表、回执还没有链接的交付目标补链接；回执和发布记录的链接一起更新。`list_publish_targets` 同时列出「已发表但缺链接」的目标。
- 效果复盘对上我们自己的发布记录时，平台数据里有链接就顺手补进回执和发布记录。

## 不做
- 视频号、百家号、B站、头条等其他平台的数据项和说明：登录或试跑后逐个加。
- 定时自动复盘：先手动说「做一次效果复盘」触发。
- 不改效果复盘页面。
