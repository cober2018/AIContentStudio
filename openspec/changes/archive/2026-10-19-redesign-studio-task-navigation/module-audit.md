# 全站页面与功能盘点（2026-10-19）

## 检查方法与边界

以App.tsx全部注册路由为覆盖基准，读取各主模块的标题、动作、页签、表单与页面组织，结合NorthStar V2第6/17节、既有商品/角色分步设计。MCP代码图本会话未提供工具，使用定向源码检索。此处是产品结构审查，不是对所有底层服务、每个字段或全部线上页面的功能验收。

## 具体子功能去向（不丢功能）

- 项目：创作任务书、来源证据、项目素材、内容矩阵、渠道变体、执行、版本、活动仍保留；概览显示下一件待办，历史不与编辑表单同屏。
- 身份：品牌/角色/账号/栏目、表达视觉、观点边界、创作配置、工作流偏好、内容记忆、公开平台身份、栏目账号形态绑定均保留。品牌与继承放角色设置，账号可单独管理；商品账号不强制走角色建档。
- 素材：上传、AI生成、检索、版本、配乐标签、许可、使用记录；来源导入/事实包/本地知识引用保留不同语义，不把收藏等于证据或授权。
- 学习：发布回填、外部历史导入、观察与更正、同口径分析、insight、候选、支持/反对证据、审核、明确提升、记忆修订归档保留；常用页面讲清结果，高级表单各有独立入口。
- 设置：模型厂商、任务路由、生成能力、来源储备/Connector、渠道方法、规则模板、方法库、团队权限、运行状态和兼容工具分别归位；真实远端支持、队列状态不可伪造。
- 旧工具：Topics→Workspace→ReviewPublish、FactPacks、Materials、Sources、Handoff、Workflows、Templates保留原合同；Dashboard/legacy/assets/review/landing只作兼容，不增加主导航。

## 与产品架构的一致性

1. 数据→发现→策划→创作→适配→分发→复盘→学习仍完整，只重排用户页面。
2. 项目仍是业务容器，不把原型中的作品卡当作新的数据库根。
3. 角色身份为长期资产，商品SKU为独立长期资产，共用媒体/AE/Resolve底层；商品不依赖角色。
4. 自动化负责给出建议与执行已授权任务；主题选择、事实引用、内容审批、账号授权和长期方法启用保持明确决策。
5. 不重新评分旧机会、不覆盖历史、不把人工修正标成模型重评；现有自然批验收独立继续。

## 后续实施顺序（需原型确认）

先机会与今日工作台；再整理作品队列与项目入口；再审阅交付；随后长期资料（身份/素材/学习）；最后必要的设置目录整理。每批复用当前API，若能力缺失先列缺口，不用静态文案冒充自动化。
