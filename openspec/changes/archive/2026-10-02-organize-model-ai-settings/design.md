## Context

基线为本地 `main@931915d` 与保留的未提交 F7/F8/模型配置改动。用户已确认连接恢复，并明确“先只整理模型与 AI”。当前 `ProductSettingsPage` 的模型分区同时展示两个可编辑配置组件、Provider 指引，并可嵌套完整旧 Settings 页面。

现有登记和能力接口共享版本化配置真源，但提交 envelope 不同。视觉融合不能伪装成一个跨接口的原子 Save，也不能恢复旧无版本 writer。`/legacy/settings` 及其他五个产品设置分区保留原样。

## Goals / Non-Goals

**Goals:**

- 让用户先看懂“有哪些厂商/模型、各功能用谁、媒体能力如何补齐”。
- 只改模型分区，复用老版中性灰、白色面板、紧凑表单和局部侧导航。
- 降低默认页面的信息量，保留真实能力、角色、版本和显式保存反馈。

**Non-Goals:**

- 不改 CPA/MiniMax 连接、默认/路由数据、协议实现、数据库或迁移。
- 不调整其他设置分区、全局导航或生产工作台。
- 不自动获取模型、测试连接、调用生成、接受素材或写本机 CLI。
- 不新增测试代码、设计依赖、配置真源或一套新的表单框架。

## Decisions

### 1. 三个局部视图，共用一个配置页面壳

保留外层六分区导航。仅模型分区内部采用约 11rem 的侧导航和弹性主面板，屏幕变窄后导航改为横向可滚动；不再加载完整旧设置页作为子页面。

| 局部导航 | 主面板 | 默认收起的细节 |
| --- | --- | --- |
| 厂商与模型 | 厂商摘要、编辑/API Key、获取/手动补录、注册模型列表 | 精确 endpoint 风险、内部 ID |
| 用途路由 | 全局默认、功能名称—模型选择、继承说明 | 内部 purpose/profile 标识 |
| 生成能力与插件 | 模型能力、插件配置、回退顺序、单次限额 | 每项协议绑定、Provider 指引、旧兼容工具入口 |

默认落在厂商与模型。左侧提供每个视图一句用途说明，右侧只显示当前视图。主标题只保留一层；避免多层卡片包卡片、冗长协议说明和版本号占据标题。

方案对比：只加折叠面板改动少，但流程仍混在一页；直接恢复整个旧页会丢失新版登记/CAS并影响其他分区。本方案复用已有状态与动作，局部组织成三个工作视图。

### 2. 厂商、模型和路由各就其位

厂商以紧凑行展示名称、连接地址、密钥状态、已注册模型数量和编辑/获取动作；编辑展开字段，API 根地址保留原含 `/v1` 标签。新增厂商和手动模型登记作为局部动作展开，不占据默认大量空间。获取仍要求先保存厂商，失败保留已有模型。

已注册模型按厂商分组；名称优先用安全 catalog 的 `model_id` 和厂商名称。内部 `registered.*` 仅在技术详情显示。能力配置里没有 catalog 匹配的旧 profile，使用其可证明的绑定 model_id 或原 profile ID，不能编造厂商或模型名称。

用途路由采用对齐的表格/表单行，将全局默认放在顶部。功能标签与继承规则沿用现有七个 purpose；不新增消费者，不改变默认或静默转换配置。

### 3. 媒体能力的逐步展开与真实状态

能力声明、接口绑定、插件回退分成小节；以可读模型名展示能力摘要，仅展开被编辑项的绑定字段。回退顺序与限额保持既有字段/顺序/服务端验证，不把配置选中、聊天登记或声明能力显示成媒体 verified。

登记聊天状态与独立媒体接口状态分别标注其含义。缺少 media binding 只能说明该媒体能力尚未配置，不能给出整个厂商连接失败结论。任何 `configured/executable/verified` 显示必须来自对应已有接口，不推断、不自动探测。

Provider 协议指引放入“技术说明” disclosure，仅在用户展开时加载。旧兼容工具以 `/legacy/settings` 链接保留，清楚提示适用范围，不能再嵌入全页或让旧 writer 覆盖新配置。

### 4. 保留配置状态的所有权与独立保存

`ModelRegistrationSettings` 继续拥有厂商、待登记模型、默认/用途选择的同一草稿；添加显示视图参数或在稳定父组件中组织，不因厂商/用途视图切换卸载。`ModelRoutingSettings` 保留独立能力草稿。隐藏面板不提交、不丢弃编辑；不把两个接口变成一个伪原子保存。

同一配置草稿的 Save 明确说明其范围，列出隐藏视图的未保存部分；登记/路由与能力保存栏分别显示未保存/保存中/已保存/失败。跨接口保存推进同一 revision 时，另一份旧草稿由服务器返回 409；保留草稿和明确重读选项，不自动覆盖或静默重试。

密钥留空保留、显式清除、脱敏、actor 切换清理、角色禁用、异步响应隔离与原有 dirty 保护必须保留。内部视图切换保留草稿；父组件汇总登记/路由与能力编辑器的 dirty 通知，离开模型一级分区时沿用明确丢弃确认或阻止导航，不能无提示抹掉本轮编辑。

### 5. 视觉与性能

复用现有 Tailwind/组件；统一 slate 文字、白面板、细边框与小范围强调色。信息标题 14–16px，正文/表单保持可读字号；技术备注次一级。可操作控件具备关联 label、键盘焦点和明确 active state；状态使用文字，不仅颜色。

初始视图不加载 Provider 指引或完整 legacy Settings。保持 Settings lazy closure，其他路由预算不退化。小屏导航、表格、输入和保存栏不产生页面级横向溢出。

## Risks / Trade-offs

- 两个编辑器共用 revision，连续保存可能冲突 → 保留各自完整 envelope/CAS，显式显示冲突，不伪造一键全存。
- 为减少默认内容而卸载组件导致草稿丢失 → 保持状态 owner 稳定，内部切换仅改变可见区域；跨一级分区采用 dirty 提示。
- 简化状态文案时夸大连接/验证 → 所有状态限定在对应能力，保留原因和安全详情。
- 当前工作区存在大量其他改动 → 只修改列出的前端布局文件，不回退旧副本或整树提交。

## Migration Plan

无数据迁移、依赖安装或配置回填。用户确认提案后在本地 main 成批完成；可通过撤销本切片的布局变更回到当前 UI，配置记录无需修改。完成后只同步本 change 的新增 product-settings 要求并归档，不同步其他 active change。
