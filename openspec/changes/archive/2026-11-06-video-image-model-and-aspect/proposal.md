# 修复：generate_video_image 跟「封面生图」设置走，能指定画幅，按画幅出大图

## Why
设置 → 用途路由「封面生图」（uses.cover_image，现在是 minimax.image / image-01）没被 MCP 工具 generate_video_image 读取：它固定用「上一次成功的生图路线」（现在是 grok-imagine-image），画幅写死 9:16，像素沿用 1048576（16:9 只有 1280×720，放大到 1920×1080 会糊）。用户要给横版讲解片出 16:9 和 3:4 两张封面底图，模型在设置里选（会选 Grok）。

## 现状（已查）
| 项 | 情况 |
|---|---|
| 设置里的模型 id | 和平台生图任务用的 selected_profile 是同一套（Grok = registered.8164…，MiniMax = minimax.image），可直接用 |
| 尺寸怎么定 | 平台按「像素预算 + 画幅」算尺寸发给模型（长边最多 2048），模型回的图必须正好是这个尺寸 |
| 像素上限 | 设置里生图「单次最大像素」全局是 1048576，单次请求不能超过它 |
| Grok 实际 | 出过 720×1280 和 1080×1920，说明能按要的尺寸出、至少到 200 万像素 |

## What Changes（只动 generate_video_image）
1. **模型**：用 uses.cover_image.profile；没选、或这个模型不可用（未启用、没 key、不支持生图），退回「上一次成功的路线」，结果里写 `model_note`「封面生图没设置 / 不可用，沿用上一次的生图模型」。
2. **画幅**：新增可选参数 `aspect_ratio`（1:1 / 4:3 / 3:4 / 16:9 / 9:16）；不传用作品导演稿画幅，没有导演稿用 9:16。
3. **清晰度**：像素预算取「长边 2048 所需像素」和全局上限里较小的那个（16:9 → 2048×1152，3:4 → 1536×2048）。模型明确拒绝这个尺寸（不是结果不确定）时，退一次到 1048576 再出，结果里写明。
4. **返回**加 `provider`、`model_id`、`width`、`height`（及 `model_note`）；MCP 工具说明写上 aspect_ratio 和默认值。

## 要你定的：全局像素上限
长边到 2048 要单次约 236 万（16:9）到 315 万（3:4）像素，超过现在的全局上限 1048576。我打算上线时把设置里生图「单次最大像素」改成 **3145728**（够 3:4 的 1536×2048，也够 16:9 的 2048×1152）。
影响：素材库「生成素材」默认仍取 100 万（页面里写死了不超过 100 万）、自动补素材沿用上次的 100 万，都不变；但**图文作品「配图」那条路线没传像素，默认取上限**，上限一改它出的图会从 1024×1024 变成约 1768×1768。若不想影响它，就在配图那里固定成 1048576（多改一行）。

## 不改
素材库「生成素材」按钮、商品镜头生图、自动补素材的出图逻辑；计费、权限、存放位置照旧。

## 2026-11-06 实调后更正（用户已确认）
按 2048 长边请求时，Grok 两次回图都被平台的尺寸校验拒收（多半已计费）。改为按封面实际尺寸出：16:9 1920×1080、3:4 1080×1440、9:16 1080×1920、4:3 1440×1080、1:1 1440×1440；模型明确拒绝或回了别的尺寸时，退一次到 1048576 像素并写明。全局上限 3145728 已改，够用。

## 2026-11-06 再次更正（用户选 A）
Grok 实测最多约 100 万像素：封面生图是 grok-imagine-image 时直接按 1048576 像素出（16:9 1280×720、3:4 864×1152），不再先试大尺寸白花一次；结果写明。其他模型仍按封面尺寸请求、出不了退一次。
