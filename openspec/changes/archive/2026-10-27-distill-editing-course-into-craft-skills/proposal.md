## Why

用户下载了一套剪辑教学课（影视飓风《剪辑全能必修课》，14 集正课），由另一个 Agent 提炼成 100 张技巧卡，放在 `output/editing-techniques/`（2026-10-27）。这套课讲的是剪辑思路，演示却用的是剪映；而平台视频链用 DaVinci 剪辑、用 AE 做包装，接 MCP 的第三方模型只能读 `resolve-edit` 和 `ae-motion` 两个技能。卡片直接拿来用不了：

- 菜单、按钮和快捷键都是剪映的叫法；
- 有些是剪映独有的功能（AI 音效、主轨磁吸、自由层级、VIP 限制）；
- 有些和我们的竖屏讲解、产品视频关系不大；
- 卡片本身没有复核过，难免有重复、颗粒度不一或转写错误。

目标：把课里的剪辑思路和检查标准，变成第三方模型按 DaVinci 和 AE 能做出来的平台技能。

## What Changes

1. **梳理卡片**：100 张逐张过一遍，判定为保留、合并或舍弃，并写明理由；对照截图修正明显的转写错误。
2. **提炼思路与标准**：每个保留的技巧写清为什么这样剪、什么时候用、怎么判断做好了、常见错误。
3. **换成 DaVinci / AE 做法**：每个技巧写出 DaVinci（剪辑、Fusion、调色、Fairlight、交付页）或 AE 的具体操作；标注能否用 Resolve 脚本或 `ae_build.py` 完成。剪映有、DaVinci/AE 没有直接对应的功能，写替代做法；替代不了的只保留思路。
4. **写进现有技能**（不新建技能）：
   - `resolve-edit` 新增 `techniques/` 下按类别的条目（节奏、镜头组接、转场、声音、调色、导出、工作流效率）；
   - `ae-motion` 新增 `techniques/` 下的条目（包装与特效、抠像与跟踪、字幕与标题）；
   - 两个 `SKILL.md` 目录表加上这些条目，`edit-combos.md` 里能直接用到的思路写互相引用。
5. **选用规则**（用户 2026-10-27 补充：武器库十八般武艺，上战场只用几样）：
   - 每个技巧写「用在 / 不用在」；
   - `resolve-edit/choose.md`「问题 → 办法」选用表，放在目录最前，先读它再读条目；
   - 克制规则：默认硬切加配音节奏，每用一招要说清解决什么问题，同类手法一条片最多一两次；
   - 导演稿镜头备注写「用了什么手法、为什么」，用户审导演稿时就能看到。
6. **能进化**：每个技巧带状态「试用 → 常用 → 退役」；复盘时按用户审片的采用与修改意见调整选用表和状态。
7. **新建一个维护技能** `.codex/skills/editing-arsenal/`（本地技能，给在仓库里工作的模型用）：专门维护这整套流程——
   - 加新招：给提炼 Agent 的提示词、卡片格式、梳理规则（新增 / 合并 / 替换 / 舍弃，冲突以平台实战结果为准）、换成 DaVinci / AE 做法、写条目、更新选用表；
   - 复盘：读平台里已审片子的导演稿手法备注和用户决定，按规则升级、补「不用在」、退役，并记录理由；
   - 每次维护留一条记录（日期、加了什么、改了什么、依据）。
   通过 MCP 写稿的第三方模型只读武器库和选用表，不负责维护。
8. **统一命名**（用户 2026-10-27）：resolve-edit → `craft-resolve`、ae-motion → `craft-ae`，维护技能叫 `craft-arsenal`；旧名不保留兼容。代码只改技能名单、MCP 参数与说明、剪辑调度脚本里的名字。

不做：不把剪映步骤原样搬进技能；不复制逐字稿和截图进仓库；不新建 AE 模板（值得做成模板的只在条目里标记，以后另提）。

## Impact

- 改动：`apps/api/craft_skills/resolve-edit/`、`apps/api/craft_skills/ae-motion/` 下的 Markdown；新增 `.codex/skills/craft-arsenal/`；`video-production-handoff` 写导演稿时引用选用表。
- 第三方模型通过 `get_craft_skill` 就能读到，不需要改 MCP。
- 原始卡片、逐字稿和截图留在 `output/editing-techniques/`，不提交到 Git。
