# 实拍口播：「配音与音乐」加语速滑块

## 为什么
用户要能灵活调实拍口播的语速，作品 94 先用约 1.15 倍。现在导演稿的 dialogue 声音段要求截取长度等于放置长度（`video_documents.py:120`，报 `video_dialogue_length_mismatch`），变速写不进导演稿。

## 改什么
1. 导演稿声音段加可选字段 `speed_percent`
   - 范围 50–200，不写就是 100。
   - 长度校验改成：截取长度 ≈ 放置长度 × speed_percent / 100，允许差 ±34 毫秒（1 帧）。
   - 规范化时保留这个字段；没写的旧导演稿行为不变，哈希也不变。
2. 「配音与音乐」步骤加语速滑块
   - 只在导演稿有 dialogue 声音轨的作品显示。
   - 0.8–1.5 倍，步长 0.05，默认是当前倍速（没调过就是 1.0）。
   - 旁边实时显示「1.15 倍 · 全片约 102 秒」。
   - 成片已定稿时只读。
3. 松手保存：后端以当前主稿时间轴为准，统一换算，存一版新主稿（算用户自己的修改，不用再采用导演稿）。
   - 所有声音段写上 speed_percent，放置时间重算。
   - 镜头时长、各轨道放置时间、字幕、叠字、AE 合成时长、成片意见时间点、总时长，同一比例重算。
   - 配乐不变速，素材截取不动，剪辑时按新总长截。
   - 已有的小样 / 成片不动，下次开剪按新时间轴（和重新生成配音一样）。
4. 规则文字同步
   - `video_chain.py`「口播声音」那条：声音段有 speed_percent 时按它变速并开音调校正；和这段口播同步的实拍画面同速，保住口型。
   - craft-resolve `techniques/sound.md`「声音轨口播衔接」第一条：「不变速」改成「不变速，除非声音段写了 speed_percent」，补 `SetSpeed` 带 PitchCorrection、对应实拍画面同速。
   - MCP `save_director_draft` 说明里的 dialogue 字段加 `speed_percent?`，第三方模型重存导演稿时才知道要带上它。
5. 导演稿分镜页显示声音段时，倍速不是 1.0 就标「1.15 倍速」，只显示不编辑。

## 不做
- 配音（TTS）作品：已有语速设置，不加这个滑块。
- 配乐变速、单个镜头单独调速。

## 验收
| 项 | 怎么验 |
| --- | --- |
| 1.15 倍 | 数据库副本上把作品 94 调到 1.15：新主稿每个声音段 speed_percent=115，总长约原来的 1/1.15；镜头、字幕、叠字同比例缩短；配乐不动；页面显示新时长 |
| 调回 1.0 | 时间轴回到原长度（每个时间点差不超过 1 毫秒） |
| 校验 | 截取 0–11500、放置 0–10000、speed_percent 115：能存；不写 speed_percent：仍报长度不一致 |
| 测试 | 现有测试全部通过（已知 5 个旧失败除外）；前端类型检查通过 |

不写作品 94 的真实主稿，核对都在数据库副本上做。
