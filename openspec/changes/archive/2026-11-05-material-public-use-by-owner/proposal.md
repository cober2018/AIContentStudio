# 自己的素材可改成可公开；采纳小样 / 成片时公开和给模型用分开判断

## Why
2026-11-05 项目 50 / 作品 95：小样（任务 53）已通过，`prepare_video_edit(phase=final)` 报 422 `video_asset_kind_or_rights_invalid`。

已在库里核实的原因链：

| 素材 | 公开 | 给模型用 | 怎么来的 |
|---|---|---|---|
| 309「知数Talk Logo」 | 否 | 是 | 用户 2026-11-01 自己上传，登记时没勾公开，没有撤销记录 |
| 546 关注卡 | 否 | 是 | AE 模板 follow-card-x 渲染，图片槽用了 309，公开权限按所有输入继承 |
| 581 小样（任务 53 输出 411） | 否 | **否** | 采纳时先试「公开 + 给模型用」，越权就两项一起关掉 |

开成片时 581 是 postproduction_parent，要求公开或给模型用至少一项为是，所以 422。
309 是用户自己的品牌 Logo，用户确认可以公开；但素材接口只有「撤销公开」，没有地方把自己的素材改成可公开。

## What Changes
1. **自己的素材改成可公开**（只能用户在页面上点）
   - 新接口 `POST /api/v1/materials/{id}/revisions/{rid}/allow-public-use`：只对「自己上传的」（source_kind upload、登记人是当前用户）、权利状态已确认（cleared）、没被撤销或归档的版本生效；其他情况拒绝并说明原因；写审计日志。
   - 素材详情抽屉在「公开发布：否」旁边加「改成可公开使用」，点之前确认一次。
   - MCP 不加这个工具；规则写明第三方模型不能用 REST 代办。
2. **采纳小样 / 成片时分开判断**：先试「公开 + 给模型用」；公开越权时，改成「不公开、给模型用」再试；这也越权（有输入不许给模型用）才两项都关。
3. **422 说清原因**：开剪辑任务时素材权限不够，报错带 message，写明是哪一镜、哪条素材、因为哪条上游素材不能公开 / 不能给模型用（顺着交付记录的输入和 AE 渲染的图片来源往上找），以及该怎么处理。
   - 例：「成片要接着用的小样（素材 581）不能给模型用也不能公开：第 7 镜的关注卡（素材 546）用了不能公开的「知数Talk Logo」（素材 309）。到素材库把 309 改成可公开使用，重新渲染这一镜、重出小样。」
4. **已有派生素材不追溯**：546、581 的权限不改。

## 已核实，不用改
- 同样的输入再调 `render_ae_template` 会新建素材和版本，不复用 546；公开权限在渲染那一刻按输入的当前权限算。所以 309 改好后重渲染，新版本就是可公开的。验证时会实际确认一次。

## 不在本次范围
- 不追溯修改已有派生素材；不加 MCP 工具；不改别人上传或网上来的素材的权限规则。
- 不动 persona-cover-template 的未提交改动，两条线分开提交。

## Impact
- 后端：`services/materials.py`、`routers/materials.py`（新接口）、`services/video_chain.py`（采纳时分开判断）、`services/content_masters.py`（422 带原因）、`services/creative_mcp.py`（video_asset_ 报错原文透传给模型）。
- 前端：`MaterialDetailDrawer.tsx`。
- 生效要重启 API；不改表结构。309 本身由用户在页面上改。
