## ADDED Requirements

### Requirement: Two daily Personas have explicit usable production configuration
The workspace SHALL persist explicit valid Text, Graphic and Audio production configuration for the technology and lifestyle Personas through existing versioned configuration, including real supported voice IDs and actual model capability bindings. Audio SHALL retain the existing explicit project Recipe selection on an accepted Text Unit rather than introducing an Audio ContentUnit modality or Persona audio default Workflow. Runtime readiness SHALL retain accurate unavailable or partial reasons and MUST NOT infer remote verification from registration.

#### Scenario: Daily default configuration is saved
- **WHEN** the operator completes each Persona configuration under the user's delegated authority
- **THEN** a reload and newly created Unit resolve the intended Persona revision, Text/Graphic modality defaults, configured model and explicit real voice without missing configuration; the saved project Audio Recipe uses the accepted Text Master

### Requirement: Six normal product flows produce newly accepted persistent artifacts
Each Persona SHALL complete a fresh normal-product Text, Graphic and Audio flow with real configured providers and existing rendering. The normal page SHALL support preview, explicit execution, result review and explicit adoption; accepted final artifacts SHALL survive reload with exact provenance, immutable material references and decodable real bytes. Existing historical or isolated artifacts MUST NOT stand in for these fresh flows.

#### Scenario: User opens the completed production projects
- **WHEN** the user opens each new project after the operator's full run
- **THEN** the actual accepted article, rendered graphics and synthesized audio are accessible with current saved Master or accepted existing audio truth and real result history

### Requirement: Daily production preserves honest evidence and media rights
The operator SHALL prepare explicit source, Brief and FactPack boundaries for the actual content, distinguish verified facts, architecture opinions and fictional lifestyle scenes, and preserve exact material public/model/commercial permissions. Existing currentness, missing-evidence, identity, permission and Unknown guards MUST NOT be bypassed to manufacture a successful run.

#### Scenario: A new lifestyle project lacks current factual evidence
- **WHEN** the selected task requests current facts but has no qualifying evidence
- **THEN** execution remains blocked until actual qualifying evidence or an explicitly scoped non-current fictional task is prepared through the existing product contract

#### Scenario: Operator explicitly permits original evidence for model use
- **WHEN** the operator opens a draft FactPack item created from their own cleared source
- **THEN** the normal page independently shows and edits model-use permission through the existing patch contract, defaults it to false, preserves separate public permission and refuses edits after freezing

#### Scenario: An article requires a real cover
- **WHEN** the operator selects a cleared exact image MaterialRevision from project shared assets for an article whose platform requires a cover
- **THEN** the normal Master and Stage-candidate editor allow explicitly setting that real image and its exact reference to the cover role through the existing save contract, preserve SHA/rights/block consistency, and leave required-media validation intact

### Requirement: Real provider execution is bounded and uncertain requests are not repeated
The acceptance batch SHALL use existing per-operation hard limits and an explicit operator ledger of at most 80 dispatched or conservatively reserved supplier attempts, serial top-level execution or acceptance actions with at least ten seconds between their starts, at most two image submissions and two TTS submissions, and each TTS output capped by the existing 360-second ceiling. Existing internal QC semantic calls SHALL be accounted for separately from Stage LLMRun rows and MUST NOT be claimed to have the operator-level ten-second interval; each QC operation reserves up to two supplier attempts before it starts. Unknown requests MUST retain their original identity without automatic replay or provider switching. Unknown prices MUST NOT be treated as zero or as proof of a monetary ceiling.

#### Scenario: A billable request outcome is Unknown
- **WHEN** a normal-page execution may have reached the supplier but has no confirmed result
- **THEN** the operator preserves and investigates that original task and stops that chain without resubmitting it

### Requirement: Readiness claims use actual final quality and normal entry evidence
The final handoff SHALL include six actual new artifact/flow receipts, reload and current-QC results, delegated AI quality criteria and methods, usable normal product links and any remaining material blockers. AI analysis MUST NOT claim direct human audio listening or undisclosed unavailable semantic checks as passing. The operator SHALL claim directly usable production only when required daily configuration and all six actual flows are complete.

#### Scenario: Final readiness is assessed
- **WHEN** the operator completes the six flows and quality review
- **THEN** the handoff states the real configuration/runtime/source revision, current access and actual remaining boundaries, without equating archive, local commit or local artifacts with public publication

### Requirement: Operational enablement preserves existing work and data
The operator SHALL make a consistent private database, media and configuration backup before formal writes, preserve old business rows except the explicitly intended append-only configuration changes, and preserve previous archives and adjacent source modifications. Any necessary code fix SHALL stay within this approved change and be reviewed before selective local commit.

#### Scenario: Enablement and acceptance finish
- **WHEN** the operator closes the daily-production change
- **THEN** old records and materials are accounted for, prior archive hashes remain unchanged, adjacent source changes are preserved, and only owned documentation and necessary code enter the local commit
