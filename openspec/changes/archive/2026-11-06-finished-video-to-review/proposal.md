# 成片定稿后作品状态变「已成稿」，自动送进审阅与交付，并打通到效果复盘

## Why
作品 95 成片已定稿，作品清单仍显示「草稿」，审阅与交付里也没有它。实测（库副本 + 真实接口）：
- 作品状态 `content_unit.status` 只能在「编辑内容单元」里手改，平台从不自动改；实际只出现 draft / archived。
- 审阅与交付要先「冻结待审版本」（v4 候选），视频作品冻结被拦（readiness_blocked）：没选渠道、没有「平台渲染确认」（视频链在达芬奇里剪，不产生这个）、导演稿里所有镜头素材都要算进去并逐条查权利字节。之后的审批、授权、成品包、审阅预览每一步都会对照导演稿重查一遍，所以同样过不去；回填凭证和效果复盘同步只看哈希一致，不卡。
- 审阅中心里所有作品的待审版本都是 0；商品作品显示「受阻」。

用户确认：作品成稿后状态要改对（留在清单里，类似归档），并**自动**送进审阅与交付，再到效果复盘；角色内容工作台和商品视频工作台都一样。

## 做法：给视频链成片单独一种待审版本（不走 v4 的导演稿重查）
平台在审片页已经对成片、封面做过检查并由用户点了通过，所以待审版本只装「交出去的东西」，只核对这些东西本身。

1. **成片通过时自动生成待审版本**（video_chain 成片通过、封面写进作品之后）
   - 内容：成片（已收下的 final 素材）、封面（横封面 / 竖版作品的封面）、竖封面（横版作品有的话）、发布文案（商品作品有的话）、导演稿版本号和哈希、作品 / 项目 / 角色快照。
   - 新的候选格式 `schema_version: 6`（成片交付），哈希覆盖全部内容；渠道取作品渠道，没选就记「待选」。
   - 只核对这几样素材：可公开使用、文件字节和哈希对得上。不查镜头原始素材。
   - 同一作品再次通过成片（比如退回重剪后）会生成新的待审版本，旧的留历史。
2. **作品状态**
   - 成片通过 → `finalized`「已成稿」；人工回填发布凭证后 → `published`「已发布」。
   - 作品清单（角色内容工作台、商品视频工作台的作品页）都显示这个中文状态；「已成稿 / 已发布」排在进行中作品后面，不消失；点进去仍能看。
3. **审阅与交付对这种待审版本的处理**（审批 / 授权 / 成品包 / 预览 / 摘要分别加一个分支，v4 不变）
   - 预览：放成片、封面（横版两张并排）、发布文案。
   - 审批：只核对待审版本里的素材和哈希仍然有效、且是这个作品最新的待审版本。
   - 授权：渠道在这一步选（待审版本是「待选」时以这里选的为准，选过后固定）；内容形态固定「短视频」；账号、动作（复制成品包 / 人工交付包）照旧。
   - 成品包 ZIP：成片 mp4、封面图、竖封面图、发布文案 txt、清单 json；不打包镜头原始素材。
   - 回填发布凭证、效果复盘同步：沿用现有逻辑（只看哈希一致）。
4. **已经定稿的作品**：上线时（等「上线」）给已定稿、且有已收下成片的作品补一次（生成待审版本、状态改「已成稿」），**不含作品 93、94**；会先列清单给你看。

## 验收
- 库副本上：作品 95 走完 成片通过 → 待审版本 → 审批 → 选渠道和账号授权 → 下载成品包（里面是成片、两张封面、文案）→ 回填发布凭证 → 效果复盘同步到这条发布记录；作品状态依次显示「已成稿」「已发布」。
- 商品作品同样走通一遍（用库副本上已定稿的商品作品）。
- 没成稿的作品不受影响；v4 / 渠道变体的老路径照旧。

## 不在范围
不改审片页、封面规则；不自动发布到平台；不动作品 93、94 的数据。
