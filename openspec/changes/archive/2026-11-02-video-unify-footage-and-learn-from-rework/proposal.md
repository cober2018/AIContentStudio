# 视频素材统一、过曝修复，以及返修经验自动带进下一条

## 为什么
1. **连续三条商品视频第一次出片都过曝。** 原因不是「按第一个镜头调亮度套到全片」，而是 iPhone HLG 实拍在达芬奇默认色彩管理下整体被提亮（平均亮度约 190，苹果相册里同一帧约 147）。2026-11-02 做 P46 时已找到办法：拿苹果系统显示帧和直出帧拟合了一组专用 LUT（`MCP/iphone-hlg-apple-sdr*.cube`，已装进达芬奇），套上后 146.8，与手机一致，不算调色。但这个办法只记在开发助手的工作笔记里，**平台给剪辑模型的规则里没有**，每条新视频都从默认设置开始，于是重复过曝。
2. **外部素材拍摄时间、场地不同，颜色、对白音量各不一样。** 现在没有「出小样前先把素材拉齐」这一步：统一色调只是可选技巧，实拍对白不要求逐段拉齐音量；平台只查整片响度，不查镜头之间亮度跳变、对白音量差。
3. **没有自迭代。** 小样/成片退回的意见只交给当前这条视频的模型改这一版，不沉淀成经验，下一条照犯。平台里的经验、记忆模块只用在文字内容上，正式库经验记录 0 条。

## 第一部分：素材统一与过曝修复

### 1.1 写进剪辑规则（平台随任务书下发的规则 + craft-resolve 技巧）
- **HLG 还原（必做）：** 每段实拍先用 ffprobe 看传输特性；是 HLG（arib-std-b67）的，项目用 davinciYRGB（不做色彩管理），只给这些片段套 `MCP/iphone-hlg-apple-sdr-render.cube`；SDR 的网络素材、AI 画面、AE 叠层**不套**。验收拿渲染文件和苹果抽帧比亮度，不看达芬奇静帧。
- **LUT 文件进仓库：** 两份 LUT 存进 `craft_skills/craft-resolve/luts/`，规则写明达芬奇里没装时先装（拷到达芬奇 LUT/MCP 文件夹）。
- **素材统一（必做，粗剪后、导出小样前）：**
  - 颜色只做校正和匹配：曝光、白平衡拉正，同一场景的镜头对齐到一个参考镜头（色彩组）。不做风格化调色；素材正常且彼此一致就不动（沿用「成片默认不调色」）。
  - 声音：实拍对白逐段拉到同一响度（目标约 −16 LUFS 对白电平），明显底噪轻度降噪，单声道只在一边的修成双声道；之后按现有混音标准（整片约 −14 LUFS、真峰值 ≤ −1 dBTP）。
- **回执写清：** 小样/成片交付时写明哪些镜头套了 HLG 还原、哪些做了颜色校正（改了什么）、哪些对白段调了音量。

### 1.2 平台交付检查（只提示，不拦交付）
小样、成片交付时，平台按导演稿时间线逐镜头抽帧、逐段测音量，在审阅页给出提示：
- **过曝：** 某镜头平均亮度过高或高光大面积贴顶。
- **亮度跳变：** 相邻镜头平均亮度差太大。
- **对白音量不齐：** 有人声的各段响度相差过大。
- 阈值放在设置里，先用保守默认值；提示里写清是哪个镜头、差多少。

## 第二部分：返修经验库（自迭代）
1. **返修记录：** 小样/成片被退回时，每条意见（已有：时间点 + 文字）照旧交给当前模型修改；同时平台把它记成一条返修记录（哪条视频、哪个阶段、意见、时间），全部留存可查。
2. **模型提炼经验：** 修好交付时，剪辑模型通过新 MCP 工具 `propose_lesson` 提交经验：原因、以后怎么做（规则）、适用范围（如「iPhone HLG 实拍」「商品视频」「某角色」）、来自哪几条返修记录。和已有经验说的是同一件事时，挂到那条经验上并累计次数，不重复新建。
3. **用户把关：** 设置里新增「经验库」：
   - 待确认的经验：同意 / 不同意（可改文字后同意）；
   - 已生效的经验：显示出现次数、来源视频，可停用；
   - 同一原因出现 2 次以上的标红提示。
4. **自动带进下一条：** 已生效的经验随任务书（`get_video_brief`）下发给剪辑模型，规则写明「先读经验，照做」；交付回执要写明这次用了哪几条经验。
5. **首批经验：** 本次把 HLG 过曝这条直接作为第一条经验录入并生效（同时也写进了剪辑规则）。

## 不改什么
- 不加新的停等环节：素材统一放在做小样里完成，用户仍只在导演稿、小样、成片三处把关。
- 不做风格化调色；不改已交付的视频。
- 经验只影响剪辑模型的做法，不自动改平台代码；需要改代码的经验仍走方案流程。
