# findings

- 现有零件：discovery_search.search（设置里的搜索，目前配置的是 MiniMax，Tavily 未配置）；url_fetch.safe_fetch（防 SSRF，不运行脚本）；/sources/url 网页文字存资料；material_search 候选只入库被选中的；商品资料图入口（product-info-images）。
- 用户决定：大平台抓不了就人工粘贴；小电商站点、品牌官网能读就自动搜；科技类搜官方渠道和高质量测评站点；挑选位置：商品在商品编辑页，科技在作品素材步骤。
- 规矩：不用别家店的价格、销量、评价；非官方图版权属于原网站，由用户决定。
- 实测（2026-11-03）：直接读苹果 / Anthropic / 大疆官网能拿到图；小米、OPPO 官网是脚本加载的空壳；OpenAI 403；三只松鼠、良品铺子官网连不上。本机 Chrome 无界面打开 OPPO 页（--headless=new --dump-dom，临时 user-data-dir，约 15 秒）读出 48 张图。
- 用户决定：加入「空壳页改用后台 Chrome 再读」；Tavily 以后再配，先用 MiniMax（只返回链接，图由平台读网页取）。
- 本机开了代理（假 IP 198.18/15），脚本里直接调 safe_fetch 会被防内网拦，平台运行时由 open_media 的代理判断放行；开发时要沿用这个处理。
- MiniMax 搜索对小众商品结果很杂（Gentle Monster、母婴店首页等），加了相关度过滤：网页标题 + 摘要和搜索词的字词重合不到一半，就归到「和搜索词对不上」。小众商品往往没有官网，搜到的多是测评、资讯文章；这类商品还是要靠人工粘贴。
- 平台的安全抓取不接受压缩响应，OPPO 官网总是返回压缩内容，所以直接读会被拒；改为：直接读失败或读出空壳时，先确认是公网地址，再用后台 Chrome 读。
- 后台 Chrome 每页最多约 20 秒，同时读 3 页；OPPO 那次 10 页里 7 页 Chrome 也读不到。
- 图片过滤：只按明显的杂图词（登录、按钮、分享、客服、二维码等）丢弃；小于 200 像素的在页面上隐藏，避免误删 /public/、/user/ 路径下的真图。
