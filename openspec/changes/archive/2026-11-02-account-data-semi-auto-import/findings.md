# findings

- 效果复盘现有结构：PublishedContentRecord（作品，origin 可为 external_import，可挂 content_account_id）+ PerformanceObservation（指标观察，追加式，有 source_type/source_ref/source_checksum）。正式库两表均 0 行。
- 现有入口只有手填、JSON 批量导入、同步 Studio 已确认发布。
- 用户核实：公众号、抖音后台可导出；小红书数据看板需申请权限；B站不能导出。
- 公众号：「数据分析 → 内容分析 → 已发表内容」有「下载数据明细」，单篇详情也可下载，限 30 天；另有官方数据接口（datacube）。来源：少数派 sspai.com/post/106184。
- 后端 venv 没有 openpyxl / xlrd，读 Excel 需新增依赖。
- 账号归属不靠文件内容猜：以用户点了哪个账号的「去数据页」为准。
- 用户确认：公众号每篇文章的数据没有下载入口，只能截图；「发表记录」列表每篇显示一排数字（阅读、点赞、分享等图标，后几个图标含义需对照后台确认）。所以公众号改走截图/复制识别。
- 四个平台里只有抖音能按作品导出，截图/复制识别成为主路径。
- 抖音「数据表现_短视频全量指标.xlsx」是账号每日合计（日期、投稿量、总播放/点赞/分享/评论、5秒完播率、2秒跳出率、封面点击率、平均播放时长），对不到作品，不用。
- 抖音「作品列表导出.xlsx」是按作品：Sheet1，表头 作品名称、发布时间(YYYY-MM-DD HH:MM:SS)、体裁(如 图文)、审核状态、播放量、完播率、5s完播率、封面点击率、2s跳出率(比率为 0–1 小数)、平均播放时长(秒，小数)、点赞量、分享量、评论量、收藏量、主页访问量、粉丝增量。样例 11 条作品。识别以这组表头为准。
- 公众号发表记录图标：爱心 = 推荐人数（用户确认）；前三个为阅读、点赞、分享；对话框、笔、带箭头方框待用户确认。
- 2026-11-02 用户改方向：截图、导出表直接丢给第三方模型经 MCP 导入，不在页面一个个上传；并要求上传的资料与数据及时清理。
- 由此去掉：页面粘贴/截图识别框、平台自调模型、监听下载文件夹、openpyxl 依赖。源文件不进平台，只存数字、文件名、校验和。
- MCP 现有工具里有 list_personas，没有账号列表和数据导入。
- 存储探查与清理规则见 proposal「5. 平台存储定期清理」；用户 2026-11-02 确认规则并要求与 MCP 导入一起开发。
- 已有清理：retention.run_retention 每日 03:30（celery beat）+ maintenance 循环。
- 「同一天」按中国时区算；发布时间没带时区的按中国时间。比率统一 0–1，模型传 23.1 这种会被拒并提示改用 0–1。
- 已知限制：当天重复导入会删掉当天旧值，若之后撤销新的那批，旧值不会回来；撤销只删这批新建的作品，匹配到的已有作品不删。
- 候选素材实际可删为 0：94 条有本地文件的候选里 76 条已归档到项目文件夹或通用文件夹、12 条所属素材已归档、4 条被 JSON 引用、2 条文件缺失。原先「107 条未挂项目」只算了直接的项目引用，偏高。
- 采集全文只清 connector 来源，且没被项目、知识集合、选题、事实包用到的；手填、Obsidian、商品页不动。
- 候选素材「删除」= 标记归档 + 无人引用时删文件（没有硬删路径，硬删会破外键）；external/ 硬盘文件、文件缺失的一律跳过。
- 生成结果已就绪但过期未采用的任务会被标成 cancelled（reason result_expired），页面不再提供采用一个已删的文件。
- 「立即清理」总会顺带 VACUUM；定时只每周一次。
