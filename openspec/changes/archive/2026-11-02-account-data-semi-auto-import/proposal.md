# 账号数据经 MCP 导入效果复盘，并定期清理平台存储

## 为什么
效果复盘只能手动一条条录入，正式库里作品和数据都是 0 条。各平台只给截图或导出表（抖音能按作品导出；公众号、B站、小红书只能截图）。用户希望不在页面上一个个上传：把截图、导出表直接丢给第三方模型，由它通过 MCP 写进平台。
同时，上传的资料和数据要及时清理，不能越存越多。

## 改什么

### 1. MCP 新增两个工具
- `list_accounts`：列出账号（编号、平台、账号名、归属角色），模型据此确定数据归哪个账号。
- `import_account_metrics`：一次导入一个账号的一批作品数据。
  - 输入：账号编号；来源（截图 / 复制文字 / 导出表，附文件名和内容校验和）；每篇作品一行：标题、发布时间、体裁（可选）、各项数据、看不清的格子列为「待确认」。
  - 数据项只收各平台固定的一组（见下），其他字段拒收，防止乱写。
  - 写入方式沿用效果复盘：按「账号 + 平台 + 标题 + 发布时间」找已有作品，没有就新建外部作品；每项数据记一条观察，注明来源和校验和。
  - 返回这批的结果（新建几篇、更新几篇、跳过几项）和效果复盘里这批的页面链接。
- 工具说明里要求模型：导入前先在对话里把识别出的表格给用户过目；看不清的数字标待确认，不猜。

### 2. 读文件、看截图都由第三方模型在本机完成
- 截图交给模型自己看，导出表交给模型自己读（抖音按作品导出表的表头已核实）。平台不再自己调用模型，也不监听「下载」文件夹，不加读 Excel 的依赖。
- 账号页保留「去数据页」按钮（用角色的 Chrome 个人资料打开作品数据页），方便去截图或导出。

### 3. 效果复盘里按批查看和撤销
- 每次导入是一批，记录来源、时间、条数。可以「撤销整批」：删掉这批写入的数据和这批新建、且没有别的数据的作品。

### 4. 清理：不越存越多
- 截图、导出表本身**不上传、不保存**，平台只存识别出的数字，以及文件名和校验和（用来判断重复）。
- 同一份文件或截图（校验和相同）再次导入直接跳过。
- 同一作品、同一数据项、同一天只保留一条：当天再次导入，用新值替换当天旧值，不叠加。不同日期保留，用来看变化。

### 5. 平台存储定期清理（用户 2026-11-02 确认）
探查（硬盘 500g 未挂载，未计入）：数据库 176M，其中采集文章全文 348 篇 94M（17 天，约 5.5M/天），补抓记录 25M；生成结果暂存 131M，53 个文件只有 3 个被素材引用；候选素材 192 条，107 条未挂项目；数据库空闲页约 24M；代码目录里两份旧库备份 285M。已有每日清理只覆盖模型调用大字段、审计、导出、工作流运行和无引用素材文件。

新增规则（天数放设置里，可改）：
| 对象 | 规则 |
| --- | --- |
| 采集文章全文 | 超过 30 天、且未被选为选题或作品来源的，清空全文，只留标题和链接 |
| 生成结果原文件 | 超过 7 天仍未采用成素材的，删除文件 |
| 候选素材 | 超过 30 天未采用、未挂任何项目的，删除；已采用素材一律不动 |
| 数据库 | 每周整理压缩一次（VACUUM） |
| 两份旧库备份 | 一次性删除，删前再问用户 |

设置页加「存储与清理」：显示各部分大小、上次清理结果，「立即清理」按钮，天数可改。
不动：已采用素材、移动硬盘上的项目文件、成片。

## 各平台数据项
| 平台 | 数据项 |
| --- | --- |
| 抖音 | 播放量、完播率、5秒完播率、封面点击率、2秒跳出率、平均播放时长、点赞、分享、评论、收藏、主页访问、粉丝增量 |
| 公众号 | 阅读、点赞、分享、推荐、留言，以及另外两个待用户确认含义的图标项 |
| B站、小红书 | 播放/阅读、点赞、评论、收藏、分享等，按用户第一次给的截图定下 |

## 不改什么
- 不登录平台、不抓网页、不定时后台运行。
- 已有的手动录入、同步 Studio 发布记录照旧可用。
