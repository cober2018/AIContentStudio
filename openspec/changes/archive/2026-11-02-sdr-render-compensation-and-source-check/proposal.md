# 普通 SDR 实拍渲染后变暗：剪辑规则补偿 + 成片与原片比亮度检查

## 为什么
项目 48 / 作品 93 成片（任务 41）：没套 LUT 的普通 SDR 实拍（抖音自拍，HEVC bt709）渲染后整体暗约 20/255，暗部到高光是固定差值，用户看出来了。iPhone HLG 片段的 LUT（render 版）本来就补了达芬奇 davinciYRGB 渲染的这个差（render ≈ 0.993·静帧 − 0.078），所以 HLG 没事。现行规则写的是「SDR 网络素材、AI 画面、AE 叠层一律不套」，普通 SDR 实拍因此吃了这 20 级。
剪辑模型已在达芬奇 LUT/MCP 下做了补偿 LUT `sdr-render-comp.cube`（整体 +0.078，即 +20/255）。

## 改什么
1. **剪辑规则与 craft-resolve（color.md、finishing.md、video_chain 规则）：**
   - 普通 SDR 实拍在 davinciYRGB 项目里也要补这 20 级：套 `MCP/sdr-render-comp.cube`；或者查出根本原因（渲染电平、数据范围等设置）从设置上解决——选了设置方案就全片统一、不再套补偿 LUT，回执写明用的是哪种。
   - HLG 实拍照旧套 HLG 的 render 版 LUT（已含补偿），不要再叠补偿 LUT。
   - AI 画面、AE 叠层：是否同样变暗未验证，规则要求渲染后抽帧和原图比一次，变暗同样补偿。
   - `sdr-render-comp.cube` 收进仓库 `craft_skills/craft-resolve/luts/`，写安装说明。
2. **交付检查新增「成片与原片比亮度」**（只提示，不拦）：
   - 对画面来自视频素材的 SDR 实拍镜头，取镜头中间同一时刻：成片里的这一帧，对应原片（按时间线片段的截取起点 + 镜头内偏移）的这一帧，比平均亮度；
   - 差超过阈值（默认 8 级，设置里可改）就在审阅页提示「第 N 镜成片比原片暗/亮 X 级」；
   - HLG 原片不比（ffmpeg 直接解出的 HLG 帧和手机显示不一致，比了没意义，HLG 靠现有的过曝检查）；原片打不开（硬盘没插）就跳过。
   - 用任务 41 的成片验证能拦住。

## 不改什么
- 不自动改成片；现有过曝、跳变、对白检查不变。
