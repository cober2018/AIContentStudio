## Context

角色工作台以 ContentUnit 为创作清单项。当前界面缺管理入口；旧 DELETE 有历史时归档、无历史时物理删除。工作区存在相邻商品工作台改动，实施须以当前代码为准并保全。

## Goals / Non-Goals

目标：每条角色作品可明确归档、恢复、删除；保留项目及被引用历史，界面与后端含义一致。
不包含：批量删除、回收站、物理文件清理、项目删除重构、商品工作台新增菜单、自动生成/发布及相邻流程返修。

## Decisions

1. 清单卡片增加“更多”菜单。默认显示当前内容；沿用“包含归档历史”，归档项明确标识并可恢复。归档隐藏当前作品，原稿、素材和历史不变。
2. ContentUnit 使用独立生命周期字段表示 active/archived/deleted，保留制作状态。加法迁移不覆盖历史 status；旧 archived 继续按原规则只读。恢复只针对本入口显式归档且父项目可编辑的单元；被身份替换的旧版本不自动恢复。
3. 新增显式生命周期操作接口，复用项目权限与审计；旧 DELETE 保留兼容合同，新菜单不使用它。归档、恢复、删除重复请求不产生重复变更；客户端失败不先移除卡片。
4. 删除确认框明确作品名称和含义：“从创作清单移除；项目、共享素材及已引用历史保留”。删除采用逻辑标记，从当前及归档清单排除，不提供本轮恢复入口；审计和已保存历史引用仍可读取，不能再作为活动作品编辑或启动制作。
5. 共享列表投影和单元可变性校验尊重生命周期，避免其他入口重新暴露可编辑的已删除单元。执行中的任务须先完成或通过已有取消流程处理，供应商 unknown 明示待核对，不以归档/删除自动重试或取消。校验与变更须在同一事务中执行，避免检查后新任务启动。
6. 先备份，再迁移与部署；沿用既有检查和隔离验证数据验证操作，不删除用户样片。最终回读正常页面与 API。

## Risks / Trade-offs

- 逻辑删除保留存储占用：本需求是清单整理，物理清理另行授权。
- 旧归档同时承载版本替换：只恢复明确由新操作归档的单元，旧历史继续可读。
- 共享入口遗漏可能导致已删除作品被继续写入：实施时检查已有单元写入与运行入口，不扩大到无关模块。

## Migration Plan

备份数据库与受影响文件，新增字段默认 active；读侧兼容旧 status=archived，不改旧记录含义。验证失败回退本轮代码和迁移，保全同期其他改动。验收后同步新增 canonical spec 并归档。
