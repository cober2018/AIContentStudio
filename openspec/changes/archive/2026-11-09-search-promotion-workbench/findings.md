# findings

- 现有「检索」检查只查标题长度（`text_master_checks._discoverability`）；profile 里写前/写后字段一直没执行。
- 工作台先例：商品视频工作台用 `production_domain=product` + `/production?workspace=product`，后端共用链条。
- 外部依据：GEO 论文（KDD 2024）——加有出处的原话/数据、标注来源效果最好，堆关键词反而降低；国内实测：元宝多引公众号，豆包多引抖音/头条，DeepSeek 用全网（行业口径，只作量级参考）；搜一搜看标题、摘要、首段。
- 决定（用户确认）：单独工作台；推广对象独立维护、不和商品混用，资料以自由描述为主；分类用两层方案（4 个固定大类、小类可维护），「面向谁」单独选；只推品牌也走「品牌与机构」大类；形态只有文字、图文、视频；平台版本不绑账号、可转给别人发，平台不跟踪发布后；角色和商品作品发自己账号并跟踪；通用能力（含剪辑特效）复用；引用监测不在本期。
- 渠道版本本来就允许不带账号（`channel_variants.resolve_target_account` 传 None 返回 None）。
- 实现决定：推广对象的事实在「确认规划」时冻结为项目事实边界（证据类型 third_party_quote，出处写进 statement），这样证据检查、事实检查、候选血缘全部复用；代价是确认规划至少要一条带出处的事实，推广对象事实改了以后再确认新规划，旧作品要重存稿。
- 搜索推广主稿不分平台冻结和审批（候选渠道记为 unassigned），交付时再选平台；平台版本（渠道变体）照旧可做。
- 检索检查只对文字主稿；图文、视频作品拿到同样的写作简报，检索规则暂不检查。
- 公众号平台版本需要先在变体页做标题映射（老规则，角色作品也一样）。
- 全量测试里 5 个失败（3 个迁移降级测试、1 个插件、1 个 schema 默认）在改动前代码上同样失败。
- 2026-11-09 用户纠正：流程不能按「人填表」设计；人只把关基础资料和最终成稿，中间全部 AI 做；模型选择、平台/第三方写作、平台 skill 开关与角色内容、商品视频工作台保持一致。
- 2026-11-09 调研：成熟写作产品按「体裁」（教程/指南/对比/测评/榜单）和「品牌口吻」两个维度区分内容；blog-kit 用体裁模板 + 组件（引用、数据、对比表、问答、优缺点）；HubSpot/Wix 2026 数据：榜单、对比、产品页、文章最常被 AI 引用，ChatGPT 对比类引用率 95%；国内共识：开头直接回答、讲依据、讲适用条件，忌绝对化用词。
- 2026-11-09 用户确认：推广项目 = 一篇核心稿及衍生，形式与基调按项目；问题库挂推广对象；视频沿用视频链条停点（成片即第 2 关）；图文成图由写作模型判断；事实在开项目时冻结；品牌说法/禁用词按推广对象共用；批量开项目单次最多 5 个；稿件包附「广告」提醒；不改另外两个工作台。
- 2026-11-09 渠道版本原规则：改写过的版本（非机械适配）证据检查一律 incomplete；搜索推广版本改为按项目事实边界做事实复核（确定性数字检查 + 写作模型复核）。
- 2026-11-09 本机代理 fake-IP 会把域名解析到 198.18.x.x；正式运行配置 runtime.env 已有 SSRF_ALLOW_PRIVATE 豁免，后端抓取正常。命令行测试要先加载 runtime.env，否则会误判为抓不到。
- 2026-11-09 用户确认：平台模型路径也自动化，复用第三方模型路径的同一串平台功能由后台执行，不走角色内容的分阶段创作流程；本期只做文章；角色内容、商品视频的简化另开提案。
- 2026-11-09 公众号版本 profile 要求封面（cover_required），封面从核心稿的 cover 素材引用带过去；公众号格式里的摘要只有带官方排版 HTML 才允许，改写版只交标题和正文。用户选封面由 AI 生成（已授权计费）。
